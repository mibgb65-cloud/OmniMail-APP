## 1. 阶段划分

| 阶段 | 目标 | 出口标准 |
| --- | --- | --- |
| M0 骨架 | 工程可跑通 | 空窗口启动、前后端打通一次调用、CI 绿灯 |
| M1 核心收发 | 单账号可用 | 收、读、写、发、删除全链路 |
| M2 多账号与同步 | 稳定日常使用 | 3 账号并行、IDLE、断线恢复 |
| M3 搜索与体验 | 找得到、用得顺 | 本地索引、快捷键、托盘、主题 |
| M4 发布 | 可分发给外部用户 | 安装包、签名、自动更新、检查单全过 |

## 2. 时间线（按迭代，不绑定具体日期）

```
M0 ── 迭代 1                骨架 / CI / 日志 / 配置
M1 ── 迭代 2-4              账号接入、收信、读信、写信、发信
M2 ── 迭代 5-6              同步引擎、多账号、离线队列
M3 ── 迭代 7-8              搜索、桌面集成、主题与可访问性
M4 ── 迭代 9                打包、签名、更新、发布文档
```

> 每个迭代 1 周，出口即"可演示的可用增量"。延期只允许砍范围，不允许牺牲出口标准。

## 3. 里程碑与交付物

### M0 骨架
- [ ] 仓库结构落定（`internal/*`、`frontend/src/*`）
- [ ] Wails 应用启动 + 单一窗口 + 菜单
- [ ] `bridge` 一个健康检查方法打通前后端
- [ ] 结构化日志 + 日志文件轮转
- [ ] CI：lint / vet / test / build 三平台
- [ ] 本文档目录成型

### M1 核心收发

- [ ] 邮件列表 + 详情（安全渲染）
- [ ] 撰写 + 草稿保存 + SMTP 发送
- [ ] 已读/星标/删除本地状态机

### M2 多账号与同步

### M3 搜索与体验

## 4. 质量目标（伴随每阶段）

| 指标 | M1 | M2 | M3 | M4 |
| --- | --- | --- | --- | --- |
| `service` 测试覆盖率 | 50% | 70% | 75% | 75% |
| 启动时间 | ≤ 3s | ≤ 2s | ≤ 1.8s | ≤ 1.5s |
| 内存（3 账号） | 无门槛 | ≤ 400MB | ≤ 300MB | ≤ 250MB |
| 已知 P0 缺陷 | 允许 | ≤ 2 | 0 | 0 |

## 5. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 各服务商 IMAP 实现差异 | 同步失败 | 预设 + 兼容层 + 用户可见错误码（[FEAT-0004](features/FEAT-0004-sync-engine.md)） |
| OAuth2 审核周期长 | 阻塞 FR-01-3 | 先做应用专用密码路径，OAuth 并行推进 |
| 邮件 HTML 渲染 XSS | 安全 | 沙箱 iframe + CSP + 资源拦截（[FEAT-0007](features/FEAT-0007-safe-html-render.md)） |
| 中文分词质量 | 搜索体验 | 二元分词基线，预留可替换分词器（ADR-0003） |
| Wails 版本迭代快 | 升级成本 | 锁定版本，升级走独立 PR + 回归测试 |
