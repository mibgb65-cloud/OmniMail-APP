# OmniMail 项目介绍

> 状态：草稿 | 负责人：@product-owner | 最后更新：2026-10-15
> 相关：[功能需求](requirements.md) · [总体架构](../02-architecture/overview.md) · [路线图](roadmap.md)

---

## 1. 一句话

**OmniMail 是一个本地优先（local-first）的多账号邮件客户端**，桌面端基于 Wails（Go + React），
让用户在一个窗口里管理全部邮箱，数据存在本机，不经过我们的服务器。

## 2. 要解决的问题

| 痛点 | 现状 | OmniMail 的做法 |
| --- | --- | --- |
| 多邮箱来回切换 | 3 个网页标签 + 2 个客户端 | 统一收件箱，账号维度一键筛选 |
| 搜索慢、找不到旧邮件 | 依赖服务端搜索，跨账号无法搜 | 本地 SQLite 全量索引，毫秒级跨账号检索 |
| 隐私顾虑 | Web 客户端有跟踪、广告 | 纯本地存储，无遥测，凭据进系统钥匙串 |
| 桌面端体验重 | Electron 体积大、内存高 | Wails：复用系统 WebView，安装包与内存显著更低 |
| 离线不可用 | 断网即空白 | 已同步内容离线可读、可写草稿、可排发 |

## 3. 目标用户

- **主力用户**：同时维护 2-5 个邮箱（工作 / 个人 / 项目 / 客户）的知识工作者。
- **次要用户**：需要离线阅读归档邮件、对数据存放位置敏感的用户。
- **非目标**：企业 IT 统一管控场景、需要团队共享邮箱的团队版（见 §6）。

## 4. 能力范围（v1 目标）

- 多账号接入：IMAP/SMTP（含常见服务商预设）、OAuth2（Gmail / Outlook）。
- 统一收件箱 + 账号/文件夹/标签三个维度的视图。
- 本地全文检索（主题、正文、发件人、附件名）。
- 撰写：富文本/纯文本、附件、草稿自动保存、延时发送。
- 会话（thread）聚合、已读/未读/星标/归档/删除。
- 桌面能力：系统通知、托盘常驻、快捷唤起、深链接。
- 离线优先与可恢复的后台同步。

## 5. 非目标（v1 明确不做）

- 不做自建中转服务端；不托管用户邮件。
- 不做日历、通讯录同步（v2 再评估）。
- 不做移动端（Android/iOS 为独立端，只共享文档与协议约定）。
- 不做团队共享、审批、审计日志。
- 不做邮件加密/签名（PGP/S-MIME）——见 [ADR 待定](../02-architecture/adr/README.md)。

## 6. 差异化

1. **本地索引**：搜索不依赖服务器能力，跨账号一次查询。
2. **轻**：不打包 Chromium，冷启动与常驻内存目标见 [roadmap](roadmap.md#4-质量目标)。
3. **可迁移**：配置与数据可整包导出/导入，账号凭据与业务数据分离存储。
4. **透明的同步**：每次同步的状态、耗时、失败原因对用户可见（[FEAT-0004](features/FEAT-0004-sync-engine.md)）。

## 7. 成功度量

| 指标 | v1 目标 | 采集方式 |
| --- | --- | --- |
| 首次配置到收到第一封邮件 | ≤ 3 分钟 | 本地埋点（用户可关） |
| 冷启动到可交互 | ≤ 1.5s（中端设备） | 启动阶段打点 |
| 常驻内存 | ≤ 250MB（3 账号） | 性能测试 |
| 同步失败率 | < 2% / 账号 / 天 | 日志聚合（本地统计，不外传） |
| 崩溃率 | < 0.5% 会话 | 崩溃转储本地留存 |

## 8. 仓库与各端关系

```
OmniMail-APP/
├── desktop/   本仓库主战场：Wails 桌面端（Go + React）
├── android/   独立端
├── ios/       独立端
└── docs/      仓库级跨端文档（协议、字段约定）
```

桌面端文档全部在 `desktop/docs/`，即本目录。
