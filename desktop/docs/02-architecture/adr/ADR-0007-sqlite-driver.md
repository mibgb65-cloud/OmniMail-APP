# ADR-0007 SQLite 驱动与多账号持久化基础

> 状态：已生效（用户确认提交） | 最后更新：2026-10-27
> 任务：[TASK-0030](../../07-tasks/archive/2026/10/TASK-0030-account-storage-foundation.md)

## 背景

ADR-0002 已确定本地 SQLite，但真实工程尚无驱动、迁移或账号仓储。
用户在了解其他数据库和许可证后确认继续采用 SQLite。
当前 Go 1.26、Windows 构建环境关闭 CGO，需要避免新增本机 C 编译器要求。

## 备选方案

- `modernc.org/sqlite`：纯 Go，可使用标准库 `database/sql`；有额外 Go 依赖和产物体积成本。
- `mattn/go-sqlite3`：成熟的 CGO 驱动，但新增 C 工具链和跨平台发布配置要求。
- bbolt：纯 Go KV，但需自行维护关联查询与检索能力，不符合当前关系模型。
- PostgreSQL：需要额外数据库进程，不适合当前单进程本地客户端。

## 实施决定

1. 锁定 `modernc.org/sqlite v1.61.0`，不引入 ORM 或第三方迁移框架。
2. 数据库位于已配置数据目录的 `omnimail.db`，WAL、外键、忙等待通过实际连接配置生效。
3. 首版使用单连接池串行访问，短事务内完成账号与连接配置写入；以后有读并发瓶颈再拆池。
4. SQL 迁移随 Go 应用嵌入，执行版本、校验和与迁移同事务保存；
   拒绝未知数据库、较新 schema 和已应用迁移被修改的情况。
5. 非空已知数据库在待升级时先做一致性备份，不自动降级或自动删除用户数据库。
6. 服务商预设在领域层单一列表定义，数据库只存文本代码和账号连接快照；
   不把服务商列表写进 SQL 枚举，新增预设无需迁移。
7. 第一阶段只落地账号和连接表，邮件表通过后续追加迁移实施，不采用旧草稿直接建全量表。
8. 本轮不修改 OmniMail 的项目许可证，不接入实际凭据保存或网络认证入口。

## 依赖与许可影响

- 候选模块发布于 2026-10-21，要求 Go 1.26.0；与项目当前工具链匹配。
- 驱动本身使用 BSD-3-Clause；SQLite 核心为公有领域。驱动的授权不要求 OmniMail 使用同样许可证。
- 新增 `modernc.org/libc`、`modernc.org/memory`、`modernc.org/mathutil` 等必要间接模块，
  并按 Go 最小版本选择更新少量现有间接依赖；实际清单以 `go.mod` / `go.sum` 为准。
- 二进制分发需保留驱动及适用第三方组件的版权与许可声明。安装包尚未实现，
  发布前仍需完成传递依赖及完整资产许可清单，不能据此宣称完整发行合规审计已完成。
  驱动原始许可保存在 [sqlite-driver-license.txt](../../06-release/sqlite-driver-license.txt)，
  不代表 OmniMail 的项目许可，也不是完整的传递依赖声明。
- 完整 verify 验证当前平台编译与行为；体积、启动耗时、macOS 和大规模邮件性能单独记录。

## 后果

- 好处：不需要 CGO，领域模型不依赖驱动，迁移和 SQL 都可用临时真实数据库验证。
- 成本：二进制及首次编译时间会增长；单连接不适合在事务内等待网络或钥匙串。
- 尚未实现：邮件收发、同步、OS 凭据存储、自动备份调度、邮件数据加密。
- 重新评估条件：实际查询并发达到单连接瓶颈、发布体积明显超标或驱动平台兼容性不足。
