# ADR-0009 大邮件有界读取与单封失败隔离

> 状态：提议（用户已确认方案，实现待评审） | 日期：2026-10-31 | 提议人：@Codex
> 任务：[TASK-0063](../../07-tasks/active/TASK-0063-large-mail-sync-isolation.md)

## 背景与授权

用户明确确认将原始邮件/单附件/正文上限从 40/25/1 MiB 调整为 100/50/8 MiB，
并要求单封超限不阻塞其他邮件。旧实现遇到正文错误立即结束账号同步；
已保存正文仍可读，但反复重试会命中同一待办。

本 ADR 补充 ADR-0008 的大小/失败策略，不改变正文入 SQLite、附件内容寻址、
只读 BODY.PEEK、已读回写门禁与既有远端删除/UIDVALIDITY 语义。

## 备选方案

- 只提高 MIME 常量：数据库 CHECK、缓存导出、HTML 清洗与连接预算仍会拒绝，不能采用。
- 取消上限或在内存拼整封：扩大资源耗尽风险，不能采用。
- 只在内存跳过错误：重启后重复下载，无法准确显示未完成项，不能采用。
- 持久单封原因、继续可处理范围（采用）：保留摘要/旧内容，明确部分完成，不吞掉其他故障。

## 决策

1. 领域常量统一为原始邮件 100 MiB、单附件 50 MiB、纯文本与 HTML 的 UTF-8 字节总量
   8 MiB。附件流式落盘/哈希/租约不变，导出仍为有界内存读取。HTML 清洗入口同步支持 8 MiB。
   只有原始 HTML 而派生纯文本副本会挤占总量时，不额外保存该派生副本；原始 HTML 不截断。
2. 连接总读取预算 128 MiB；常规后台批次仍为 32 MiB、至多 32 封正文，大邮件只在尚未读取头/
   正文的新连接独占。60 秒连接/请求、续排及并发边界不变，不保证慢网络中的 100 MiB 邮件能在期限内完成。
3. 邮件头仍 1 MiB、MIME 最多 128 部件；发送正文仍 1 MiB。
   图片的单张 4 MiB、像素、数量/累计资源及远程加载授权不变，不随正文上限放宽。
4. schema v4 增加 `body_error_code` 固定白名单，只存原始邮件、附件、正文、部件数四类原因。
   网络、连接累计预算、取消、存储/清理或混合故障不得被持久误判为单封超限。
5. 后台待办排除已确认受限项。摘要原始大小可预判的直接跳过；MIME 失败会中止 FETCH，
   记录后让下一批重连，不能在已断开的会话继续。其他邮件/文件夹正常推进。
   错误记录保存失败和附件清理失败仍是可见故障，不以成功或永久跳过掩盖。
6. 不把受限项视为完整正文；`Cached` 仍只代表本地正文存在，原先已有正文可以继续离线阅读。
   账号通过数据库持久计数呈现“部分邮件未完整下载”，日志使用 `SYNC_LIMITED`，不报全量完成。
   普通同步不清固定失败。单封显式重取成功时原子清除标记；远端摘要大小变化时清标记并使正文待重验，
   保留旧缓存；原始大小仍明显超限时不提供无效下载按钮。
7. 向导/预设/凭据不变。IPC 只增加可选的邮件原因和账号受限数量；原始 HTML 不跨 IPC，
   不将未知服务器响应或邮件/账号内容写日志。仅展示受限摘要不能自动向服务商标已读。

## 迁移与恢复

- 新增 `0004_large_mail.sql`，不修改已应用 0001～0003 的校验和。
- 沿用打开数据库时的身份校验、升级前 `VACUUM INTO` 备份与立即事务；
  备份命名为数据目录 `backups/pre-migration-v0004-*.db`。
- 用替换受限列的方式放宽 HTML/附件约束，不删除父表，不触发附件级联删除。
  新正文 CHECK 按字节校验 Text + HTML；迁移/磁盘失败应整体回滚，不截断既有内容。
- 不支持无损自动降级为旧上限。需要恢复时先关闭应用并另备份当前完整数据目录，
  选择升级前数据库及其对应附件内容；升级后的新邮件/标记可能不在旧备份中。
  旧版应用会拒绝新迁移版本，不能直接替换程序后强行打开或手改迁移历史。
- 首次升级需要额外备份空间与表改写时间；大规模生产库升级耗时和崩溃恢复尚待实际环境评估。

## 验证边界

合成测试覆盖 100 MiB 原始 literal、50 MiB 流式附件、8 MiB 正文边界、旧库备份/引用保留、
迁移失败回滚、重复/重启跳过、跨文件夹继续、显式恢复、非大小/混合错误及 UI 状态。
实际命令、完整门禁与未验证的真实服务商/平台以任务记录为准。
