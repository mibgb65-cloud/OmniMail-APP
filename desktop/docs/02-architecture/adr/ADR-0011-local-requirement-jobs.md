# ADR-0011 本地待办与应用内增量需求调度

> 状态：提议（已实现待评审） | 最后更新：2026-11-03
> 决策依据：用户要求待办/跨邮件分析，明确确认运行或托盘执行、错过后启动补跑。

## 背景
单封 AI 结果缓存不是可编辑任务账本；定时调用模型也不能直接继承手动外发授权。
需要跨邮件关联、人工修改保护、重启恢复与明确的外发边界。

## 备选方案
- 浏览器定时器/localStorage：随窗口生命周期丢失，不满足托盘、事务和重启恢复。
- OS 计划任务/云服务：超出用户确认的运行边界，增加权限或改变邮件部署/隐私模型。
- 应用内 Go 调度 + SQLite：复用本地存储、单实例和关闭链，所有重要状态持久化，采用此方案。

## 实施决策
- 新增 schema v6，任务来源不对邮件行做删除级联，人工事项独立于同步重建；用户可明确清理。
- 日调度只在 ApplicationStarted 后启动/恢复，不能在构造资源、尚未确认单实例时改动队列。
- 正常 UID 建服务器基线，零 UIDVALIDITY 保守筛选；不以未读标志判定新邮件。
- 独立授权绑定 AI 配置、账号与文件夹类型，默认关闭；模型只提出候选和变更，不直接完成事项。
- 调用前登记未知收据，成功结果与事项原子落盘；只自动恢复未开始项，未知请求由用户确认重试。
- 提取服务复用 AI 单任务额度、取消与 HTTP 适配；不新增 SDK、消息中间件或向量数据库。

## 后果与限制
- 接受托盘/运行时有效、关机不执行的约束；补最近到期槽位而不逐天重放。
- 多封邮件按顺序处理，候选范围有界，可能漏关联；日期保留原文而不自动归一。
- 本地来源引文独立保留，清理邮件/AI 缓存不删除事项；界面必须明确这一点。
- 不能提供上游计费恰好一次保证；源文本已外发后取消不能撤回。
- 迁移前备份与旧版拒绝高 schema 的行为必须在交付中说明。
