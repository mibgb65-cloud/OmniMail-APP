  未实现系统凭据存储、网络认证或邮件同步。实际版本见 [当前 Schema](schema-current.md)。

- 第一阶段落地账号存储；邮件、同步与收发信暂不实现，避免把协议适配与持久化一次性耦合。

## 2. 存储边界

沿用一个本地 SQLite 数据库，不按服务商或账号拆库、拆表。

| 介质 | 数据 | 边界 |
| --- | --- | --- |
| SQLite | 账号配置、邮件元数据、普通正文、索引、草稿、同步游标、操作队列 | 不保存密码、授权码或 OAuth 令牌，包括它们的密文 |
| 文件系统 | 附件、大正文、按需缓存的原始邮件 | 不以远端文件名构造实际缓存路径；维护引用和清理边界 |
| 系统凭据存储 | 密码、应用授权码、OAuth 令牌 | 数据库只保存不含秘密的引用；平台实现遵循 ADR-0004 |

数据库和附件静态加密尚未实现。凭据隔离、操作系统登录保护不等同于邮件内容加密。

## 3. 服务商预设：单一扩展入口，不参与分表

### 3.1 概念

- 服务商预设：添加向导使用的非敏感默认配置与能力说明。
- 账号：用户实际配置的一个邮箱身份；同一预设可关联多个账号。
- 连接：账号的 IMAP 或 SMTP 配置，用户名不必等于邮箱地址。
- 文件夹：账号下的收件箱、已发送、自建文件夹或服务商标签，不称为账号。

首版预设标识建议使用 `gmail`、`qq`、`netease_163`、`netease_126`、`custom`。
标识稳定且不依赖中文显示名；上述预设已在领域层定义，尚未通过真实邮箱认证测试或接入 UI。

### 3.2 扩展约定

1. 预设随应用内置，首版不建立运行时可编辑的服务商管理表。
2. 数据库的 `provider_code` 为文本，不在 SQL `CHECK` 中硬编码服务商列表。
3. 增加服务商只增加预设定义、必要展示资源和测试，不增加账号表、不执行数据库迁移。
4. 添加账号时把预设展开成账号实际连接配置；后续预设更新不得自动改写已保存配置。
5. 读取已有账号不依赖预设仍存在；预设被移除后，已保存的连接配置仍可被读取和编辑。
6. `custom` 走相同模型，但要求用户提供实际 IMAP/SMTP 参数。
7. 服务商不决定唯一认证方式；认证类型按连接保存，不把 Gmail、QQ 等名称写成业务分支。
8. 预设只包含受审阅的非敏感信息，不包含用户密码、令牌或需要保密的客户端凭据。

新增预设的验收：两个同类型账号互不覆盖；旧账号连接快照不变；未知预设历史账号可读；
非法参数被拒绝；没有执行 schema 迁移。网络认证是否成功另作集成验证。

## 4. 第一阶段：账号及连接

### 4.1 `account`

| 字段 | 语义 |
| --- | --- |
| `id` | 应用生成的稳定本地 ID，不由邮箱地址或服务商编码拼接 |
| `provider_code` | 稳定预设标识；不作为账号唯一标识 |
| `email` | 对外邮箱地址；保留用户合法地址，不擅自移除点号或 `+` 后缀 |
| `display_name` | 用户自定义账号名称 |
| `color_index` / `sort_order` | 账号展示属性 |
| `status` | 已配置、需重新授权、已断开保留数据等生命周期状态 |
| `sync_enabled` | 用户同步偏好，与临时网络或认证错误分离 |
| `created_at` / `updated_at` | Unix 毫秒整数 |

不采用旧草稿的 `UNIQUE(email, provider)` 作为重复连接的充分判据。
同一邮箱可能经预设与自定义入口指向同一远端，也可能合法连接到不同服务器。
重复添加的交互策略在向导实施前确认；第一阶段存储不能误合并或覆盖已有账号。

### 4.2 `account_endpoint`

| 字段 | 语义 |
| --- | --- |
| `id` | 本地连接 ID |
| `account_id` | 所属账号，外键 |
| `protocol` | `imap` 或 `smtp` |
| `host` / `port` | 已校验的主机及端口 |
| `tls_mode` | 隐式 TLS 或 STARTTLS，不提供静默降级到明文 |
| `username` | 实际登录用户名 |
| `auth_kind` | `password` 或 `oauth2`；授权码属于密码类凭据 |
| `credential_ref` | 系统凭据条目引用，不含秘密 |
| `created_at` / `updated_at` | Unix 毫秒整数 |

约束及操作：

- `UNIQUE(account_id, protocol)`；首版一个账号至多一条 IMAP 和一条 SMTP 配置。
- 服务层保存完整账号时要求所需连接齐全；账号与连接配置在一个事务内写入。
- 两条连接允许引用同一组凭据，也允许使用不同用户名或不同凭据。
- 只接受合法主机与 1–65535 端口；不将主机输入当成 URL、路径或 shell 参数。
- 不因是自建服务器就跳过证书校验；企业内网地址不等于非法地址。
- 校验字符串类型、UTF-8、长度、控制字符、枚举和 ID；错误中不回显原始敏感输入。
- 邮箱域名与登录用户名的规范化分开处理，不默认将所有 local-part 或用户名转为小写。
- SQL 一律参数绑定，账号排序字段等动态结构只从固定白名单选择。

### 4.3 凭据一致性与账号移除

钥匙串和 SQLite 不能组成同一个事务。添加或换凭据时使用新的引用，数据库提交失败则清理
新条目；数据库提交成功后再清理不再被引用的旧条目。删除失败必须可重试、可观测且不泄密。

移除账号有两个不同操作：

- 断开并保留本地数据：停止账号任务、取消待执行远端操作、解除凭据引用并清理无引用凭据，
  保留账号身份和离线邮件；不向服务器执行邮件删除。
- 清除本地数据：在明确授权范围内清理该账号的数据库数据和不再被其他对象引用的缓存，
  不以共享文件名或服务商类型批量删除其他账号数据。

真实连通性校验和安全凭据保存尚未接入时，仓储只作为内部存储能力，不向 UI 宣称账号已可用。

## 5. 后续邮件模型：先约束，不提前建空业务表

| 实体 | 作用与关键字段 |
| --- | --- |
| `mailbox` | 账号内文件夹或标签；远端标识、角色、显示名、层级；保留服务器原始标识 |
| `mail` | 本地 ID、账号、可空 RFC Message-ID、主题、地址、时间、摘要等 |
| `mail_mailbox` | 带独立本地 ID 的服务器实例，关联邮件、账号、文件夹、UIDVALIDITY、UID、标志位 |
| `mail_body` | 正文内容或文件引用、下载状态、大小；列表查询不加载大正文 |
| `attachment` | 邮件、MIME 部件标识、原始显示文件名、大小、下载状态、可空缓存哈希和引用 |
| `sync_state` | 按文件夹记录 UIDVALIDITY、同步进度、能力相关游标与脱敏错误码 |
| `pending_op` | 目标实例、操作、同步代次、重试时间、状态与错误码；持久化离线意图 |
| `draft` | 可恢复草稿及版本，附件引用受到保护，不按普通下载缓存回收 |
| 全文索引 | 可重建派生数据，主题、地址、正文、附件名；中文检索方案仍遵循待评审 ADR-0003 |

### 5.1 标识与去重

- 本地邮件 ID、RFC Message-ID、服务商 ID、IMAP UID 各有独立语义。
- RFC Message-ID 可缺失、异常或重复，不设置 `UNIQUE(account_id, message_id)`。
- IMAP 实例使用 `(mailbox_id, uid_validity, uid)` 唯一约束；同一邮件在同文件夹可有多个实例。
- 只有可靠的服务商级稳定标识或已确认的操作结果，才能关联不同位置的同一邮件；
  不凭主题、Message-ID 或内容哈希贸然合并。
- 邮件、文件夹、会话及实例之间保证账号一致，不能只靠各自单列外键允许跨账号错关联。
- 同一内容哈希可以用于共享缓存，不代表两个服务器实例可以合并。

### 5.2 状态、同步及删除

- 通用 IMAP 服务器标志位以实例为准；列表聚合语义在邮件用例实施前明确。
- 本地已提交的用户意图与最近观察到的远端状态分离，避免同步覆盖待回写修改。
- UIDVALIDITY 改变后，旧实例操作不得直接重放到新 UID 上；先判定身份失效和冲突。
- 同一批同步数据及同步进度原子提交；UIDNEXT 是服务器信息，不等于成功处理完的本地进度。
- 移动到垃圾箱、服务器 EXPUNGE、本地缓存驱逐和用户隐藏是不同状态，不共用一个 `deleted_at`。
- 账号内操作串行；状态变更及入队同事务，队列重启后可恢复。
- SMTP 超时存在“已接受但确认丢失”的不确定结果，不宣称恰好一次发送，也不盲目自动重发。

### 5.3 正文、附件、索引

- 未下载、空内容、失败和已缓存分别表达；下载前不强制要求路径或内容哈希。
- 附件按 MIME 部件获取并流式处理，约束解码大小、嵌套深度和资源使用。
- 缓存路径由应用生成，校验解析后的目标在数据目录内；远端文件名只作显示和受控导出建议。
- 文件写入与 DB 引用提交有补偿和孤立文件回收；回收前检查草稿、队列及其他邮件引用。
- HTML 始终视为不可信内容，缓存成功不代表可直接执行或渲染。
- FTS5 使用稳定整数 rowid 映射，不直接与 TEXT 邮件 ID 比较；更新、删除和重建必须测试。
- 索引只为真实查询建立，并使用实际数据量及查询计划验证，不预先承诺性能指标。

## 6. 数据库基础设施实施门槛

1. 确认 SQLite 驱动，核对维护、许可证、FTS5 能力及对发布工具链和体积的影响。
2. 按 ADR-0002 实现 WAL、外键、短事务与单写者；连接级配置覆盖实际使用的连接。
3. 迁移 SQL 嵌入应用，版本与校验和同事务登记；拒绝未知较新版本或已应用迁移校验不符。
4. 非空库升级前进行一致性备份；不盲目复制活跃 WAL 数据库，也不提供自动破坏性降级。
5. 初始化、失败清理及关闭均检查错误和上下文；不记录邮箱、用户名、凭据或 SQL 参数。
6. 空库、重开、原子失败、外键、非法输入、取消、迁移幂等与校验异常使用临时真实 SQLite 测试。
7. 完整运行项目 verify；构建体积变化和桌面生命周期未验证项单独记录。

第一阶段的迁移仅创建已实现用例需要的账号、连接与迁移记录表。
后续邮件模型通过独立任务和追加迁移落地，已经应用的迁移不可修改。
