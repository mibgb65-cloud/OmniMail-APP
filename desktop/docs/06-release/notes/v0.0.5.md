# OmniMail v0.0.5

Windows x64 当前用户签名生产安装包，本次本地交付，不代表已发布 GitHub Release。

## 升级前请注意
- 本版数据库升级到 **schema v6**，迁移前自动创建 SQLite 一致性备份；沿用原有数据目录。
  **升级后的数据库不能直接用 0.0.4 或更早版本打开**，回退须按迁移前备份恢复，不能直接降级覆盖。
- 安装器会关闭正在运行的 OmniMail。当前撰写内容尚未持久化，请先处理未发送邮件。
- 每日分析默认关闭，原有单封 AI 授权不会自动启用后台外发，升级本身不上传邮件。

## 本次内容
- AI 区域新增“打开待办与每日分析”，提供待办、跨邮件分析、每日设置三个分类。
- 本地待办支持新增、编辑、状态、备注、来源引文和需求变更建议；人工编辑有版本冲突保护。
  AI 新事项先进入待确认，对既有事项只提出修改/冲突/取消/完成建议，明确采用后才更新。
- 跨邮件分析使用同账号、已授权范围内的有界候选事项；只发送选中标题/正文及原始提取标题/引文，
  不发送人工备注、附件或邮箱登录凭据。负责人/日期保留原文，不按扫描当天推算“明天”。
- 每日设置可选择账号、文件夹类型、时间、IANA 时区和每批上限（默认 20、最大 100 封）。
  需单独保存后台授权并启用；只在程序运行/托盘常驻时执行，错过后启动补最近到期批次。
  完全退出或关机时不执行，不创建 OS 计划任务或云端服务。
- 首次授权建立同步基线，不扫描全部历史；旧邮件可手动选择分析。
  正文未就绪、数量限额外、同步不完整均明确提示，不把部分处理当作覆盖全部新邮件。
- 处理账本与待办原子落盘，成功项不重复请求；未知结果不自动重发，手动重试需确认可能再次计费。
  提供停止、继续未开始项及最近运行记录，不把后台读取标为已读，不移动邮件或自动发回信。

## 数据与隐私
- 事项和必要短引文在本机 SQLite 保存；邮件同步移除不删除这些用户记录，清除需删除事项。
  AI/翻译缓存清理不删除待办。派生文本未声明静态加密。
- 保存分析设置会取消旧批次；账号/文件夹或 AI 配置变化须重新确认授权，
  更换 AI 配置后重新建立安全基线，不把旧授权内容悄悄交给新目的地。
- 取消不能撤回第三方已经收到的文本；AI 请求可能消耗服务方额度。
- 沿用 0.0.4 的单封 AI、DeepSeek 预设、独立系统密钥存储与 B 站翻译。

## 已知边界
- 仍为自签名代码签名证书，Windows 可能提示未知发布者/SmartScreen；不要求安装根证书。
- 应用内自动更新未启用，仍需手动安装覆盖升级；本轮不自动安装或重启用户程序。
- 首期按文件夹类型选择，不支持逐个自定义文件夹；跨账号不自动关联。
  候选池有界，可能重复/漏关联，并非全邮箱语义检索；所有变更仍需人工核对。
- 零 UIDVALIDITY 使用保守的首次观测/时间筛选，异常日期与历史导入/移动场景需手动核对。
- 未使用真实邮件/Key 做 DeepSeek 公网质量验收，未执行真实 0.0.4→0.0.5 数据迁移、
  生产覆盖升级、原生托盘连续运行/休眠唤醒及 macOS/Linux 原生验收。
- 没有向量库、附件/OCR、日历或系统通知接入，不自动完成事项或发送邮件。
