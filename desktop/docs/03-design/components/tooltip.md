# 悬浮提示 Tooltip

> 状态：已实现 | 最后更新：2026-10-29
> 相关：[TASK-0042](../../07-tasks/archive/2026/10/TASK-0042-unified-tooltips.md)

## 用途与入口

统一应用内短说明、图标动作名称、禁用原因和截断文本的悬浮提示，替代原生 DOM `title`。
`App` 只装配一次 `TooltipHost`，现有控件通过属性声明，不加外层包装，不改变布局或焦点顺序。
不替代确认对话框、系统菜单、表单错误或必须持续可见的业务说明。

## 声明属性

| 属性 | 含义 | 默认 |
| --- | --- | --- |
| `data-tooltip` | 已翻译的纯文本提示，空白或超过 1024 字符不展示 | 无提示 |
| `data-tooltip-side` | `top` / `bottom` / `left` / `right`，允许从祖先继承 | `top` |

优先方向只是偏好；空间不足会翻转，再限制到视口内。侧栏偏好右侧，其余默认上方。
宽度上限使用 `--tooltip-max-width`，长邮箱或说明允许换行，不改变触发控件宽度。
Tooltip 文案复用所属功能命名空间，不新建一套翻译或持久化状态。

## 状态与视觉

- 指针悬停 400ms 后出现；离开后预留 120ms，允许跨过间距移入提示继续阅读。
- 键盘聚焦立即显示；按下/点击、页面滚动、窗口失焦/缩放、触发器卸载或隐藏立即清理。
- 触屏指针不通过悬停打开提示，不拦截点击；禁用按钮仍可通过鼠标悬停查看原因。
- 颜色、圆角、间距和阴影使用主题 Token，浅/深色自动匹配；轻量淡入/位移遵循减少动效偏好。
- 使用固定定位 Portal。模态内 Portal 留在对应 dialog；支持时使用原生手动 Popover
  升入 top layer，避免被裁剪、动画 transform 或原生 dialog 遮挡；不支持时保持普通浮层。
- 浮层只承载文本，不放链接、按钮、表单等交互内容，也不解析 HTML。

## 键盘与可访问性

- 保留触发器原来的可访问名称、`aria-describedby` 和焦点顺序。
- 展示时追加本 Tooltip 的唯一描述 ID，清理时仅移除该 ID，不覆盖其他帮助或错误描述。
- 按 Esc 先关闭可见 Tooltip，不同时关闭父级模态框；没有可见提示时 Esc 沿用原行为。
- 允许鼠标移入提示阅读，不使用额外的可聚焦包装让禁用按钮伪装成可用按钮。
- 仅有图标的按钮仍必须显式设置 `aria-label`，不能依靠悬浮提示替代名称。

## 使用示例

```tsx
<button type="button" aria-label={t('close')} data-tooltip={t('close')} onClick={onClose}>
  <UiIcon name="close" />
</button>
```

## 反例

- 不再新增 `<button title={...}>` 等原生提示；自定义组件的非 DOM `title` 业务属性不受影响。
- 不通过修改全局 HTML 类型、类型断言或新增 UI 框架来接入 Popover。
- 不将后端原始错误、凭据、令牌或真实邮件正文作为提示。
- 不将 Tooltip 当成通知弹窗，也不把仅悬停可见的内容作为操作的唯一必要说明。

## 验证边界

组件测试覆盖计时、焦点、清理、禁用按钮、纯文本、动态更新和定位；
AST 回归检查阻止已有原生 DOM `title` 返回。Chromium 验证覆盖真实 top layer、
明暗主题、中英文、边缘、窄窗口、移入与模态内双 Esc 行为。
浏览器 fixture 不验证原生桌面桥接和邮件功能，其他平台实机尚未验证。
