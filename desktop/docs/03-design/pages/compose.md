# 工作区内撰写

> 状态：当前实现待评审，下方保留历史目标 | 负责人：@design-lead | 最后更新：2026-11-01
> 相关：[FEAT-0003 撰写与发送](../../01-product/features/FEAT-0003-compose-send.md)

## 当前实现：TASK-0073

- 左侧“写邮件”进入主工作区右侧，不再打开长期居中模态窗；有未完成会话时显示“继续写邮件”。
  保留导航/列表，暂时隐藏分析区，返回后恢复原有分析展开偏好和阅读/列表挂载。
  820px 以下撰写时暂时让出列表空间，返回浏览恢复，不为小窗口撑出长页面。
- 顶部为标题和“返回邮件”，中间发件人/收件人/主题/正文，底部固定发送（左）与放弃（右）。
  撰写期间旧阅读项的归档、删除和标记操作暂停，避免误把它们当作撰写动作。
- 有效当前账号可预选；全部邮箱只有一个可发送账号才默认，多账号或失效上下文不偷换第一项。
  账号选择器完整显示名称/邮箱、最高 240px，支持方向键、Home/End、确认、Esc 和 Tab，
  失效账号禁用；浏览账号变化不隐式更换 From，前后端发送时仍验证账号。
- 本次编辑只在 App 内存保留；临时看别的邮件或账号再返回不清空，也不取消已发起的 SMTP。
  不写 localStorage/文件/数据库，退出应用后不会恢复；不称“已保存草稿”。
  主动放弃非空内容才弹短确认，返回与放弃是不同操作。
- 收件人格式由既有 Go 地址解析器最终裁定；前端补空值、UTF-8 长度及控制字符检查。
  单行字段普通 Enter 导航，正文 Enter 换行；Ctrl/Cmd+Enter 请求发送，IME 不误触发。
  空主题/正文需当次确认，同步锁防更新前重复提交，成功/不确定状态另有终态锁。
- 服务器接受只显示“发信服务器已接受邮件”，不宣称送达；普通失败保留输入可修正。
  SEND_UNCERTAIN 及无法证明未接受的桥接取消/超时/中断均禁止直接重发，先核对服务商已发送；
  返回浏览后仍可查看发送状态。放弃不会撤回邮件，已发送副本继续由服务商处理。
- 验证记录：[TASK-0073](../../07-tasks/active/TASK-0073-workspace-compose.md)。
  本轮不实现持久草稿、重启恢复、附件、富文本、抄送/密送、补全、回复/转发、队列或撤回；
  不向用户真实账号发送测试邮件。

## 历史方案与后续目标（以下不是当前已实现行为）

### 目标与入口

写信、回复、转发。目标：输入零打断（无弹窗打断输入）、内容零丢失、发送状态清晰。
窗口模式：默认独立窗口（可并列主窗口），也可在主窗口内以覆盖面板打开。

### 布局

```
┌───────────────────────────────────────────────────────────────┐
│ 新邮件 / 回复 / 转发                                 ⌄  ✕      │ 标题条 40px
├───────────────────────────────────────────────────────────────┤
│ 发件账号：[ACCOUNT_LABEL ▾]                                    │ 字段区
│ 收件人：  [输入…            ]  Cc  Bcc                          │
│ 主题：    [                ]                                    │
├───────────────────────────────────────────────────────────────┤
│ 格式工具栏：B I U  • 1. ⌗ "</>  🔗                             │ 32px（富文本时）│
│                                                               │
│   正文编辑区（默认纯文本，等宽可选）                            │ 自适应
│                                                               │
├───────────────────────────────────────────────────────────────┤

```

### 区域与元素

| 元素 | 规格 |
| --- | --- |
| 发件账号 | 多账号时可选，切换会重建草稿归属（提示已改动） |
| 收件人 | chip 形式，支持补全（3 字符触发，本地联系人缓存） |
| 主题 | 单行输入；为空时发送二次确认 |
| 编辑区 | 默认纯文本；`min-height: 240px`，随内容增长（上限 60% 窗口高后内部滚动） |
| 附件 | 拖拽入窗或按钮选择；显示文件名、大小、上传/暂存状态 |
| 保存指示 | `保存中… / 已保存 HH:mm / 保存失败（重试）`，字号 `--text-xs` |

### 交互与状态

| 场景 | 行为 |
| --- | --- |
| 输入停顿 2s 且内容变化 | 自动保存（乐观锁，冲突提示） |
| 关闭窗口 | 有未保存改动先落盘，再关闭；失败阻止关闭并提示 |
| 发送中 | 按钮变 loading，编辑区只读（防止发送内容与界面不一致） |
| 发送成功 | 窗口关闭，Toast：`已发送` + 可撤销（3 秒内撤回为草稿，若服务器支持） |
| 发送失败（临时） | 队列中，显示 `等待重试，第 N 次`；不阻塞用户继续编辑其他草稿 |
| 发送失败（永久） | 错误条 + 修复建议（重新授权 / 检查收件人）+ 转回草稿 |
| 引用内容 | 回复时插入 `> ` 前缀引用，可折叠；转发默认附原件 |
| 拖拽附件过大 | 明确提示上限 25MB，不静默拒绝 |

### 键盘操作

| 键 | 动作 |
| --- | --- |
| `Ctrl/Cmd+Enter` | 发送 |
| `Ctrl/Cmd+S` | 立即保存 |
| `Esc` | 关闭（先保存） |
| `Tab` | 收件人 → 主题 → 正文 → 附件 → 发送 |
| `Ctrl/Cmd+Shift+V` | 粘贴为纯文本 |

### 数据依赖

`Compose.Save`、`Compose.Send`、`Account.List`；订阅 `ops:failed` 以显示发送失败。

### 验收要点

- [ ] 30 秒连续输入期间自动保存次数 ≤ 2 次（停顿触发）。
- [ ] 强杀进程后重开，正文、收件人、附件均恢复。
- [ ] 无收件人时发送被阻止并聚焦收件人字段。
- [ ] 主题为空时发送弹二次确认，可勾选"不再提示"。
- [ ] 附件拖拽区域覆盖整个窗口，hover 时显示虚线框（不遮挡正文）。
- [ ] 发送失败后可一键重试，重试后不产生重复邮件。
