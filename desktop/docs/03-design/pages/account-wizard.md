# 添加账号向导

> 状态：草稿（含当前实现说明） | 负责人：@design-lead | 最后更新：2026-10-31
> 相关：[FEAT-0001 账号接入](../../01-product/features/FEAT-0001-account-onboarding.md)

## 当前实现（2026-10-31）

侧栏“添加邮箱”打开同一模态窗内的左右分栏四步向导，不先展示完整服务器表单。
左侧显示添加进度，右侧显示当前步骤的选项与配置：

1. **选择服务商**：右侧上方可输入邮箱，本地按完整域名识别 `gmail.com`、`qq.com`、
   `163.com`、`126.com`、`linux.do`，域名匹配不区分大小写；未知域名使用自定义 IMAP/SMTP。
   输入时展示结果，点击“继续”或按 Enter 再进入配置，不在输入中途自动跳转。
   匹配仅使用真实 `Providers` 返回的服务商，不进行 DNS、Autodiscover 或网络探测；
   快捷入口限制有效邮箱格式、地址长度与域名边界，不接受显示名形式。
   下方仍按真实结果展示卡片，分为“预设服务商”和
   “自定义服务商”。当前展示入口为 Gmail、QQ 邮箱、网易邮箱、LINUX DO Mail；
   网易 163/126 合并为一个品牌卡片，底层子预设仍各自保留以兼容旧账号和正确路由，
   不把未确认的 `162.com` 当作 126 的别名。
   自定义入口为 IMAP/SMTP。卡片使用本地服务商品牌图标，自定义使用通用配置图标。
   只选择卡片或通过邮箱继续不会发起认证或保存账号。
2. **配置账号**：右侧显示已选服务商。预设仅显示邮箱地址、可选账号名称和一套登录密码，
   隐藏 IMAP/SMTP、端口、TLS、独立登录用户名及发信凭据选项；端点仍取自 Providers，
   提交时固定以邮箱作为收发信用户名，并使用同一密码，不受之前自定义配置影响。
   Gmail 使用邮箱地址和应用专用密码，不是 Google 登录密码。自定义主机留空供手动填写，
   保留完整服务器、端口、安全及共享/独立凭据能力；需要修改预设端点时选择自定义入口。
   Gmail 不显示重复填写说明，应用专用密码安全提示保留在编辑卡片上方。
   网易逐邮箱依据 `@163.com` / `@126.com` 选择真实子预设，不需要用户分开选卡；
   主机、端口与 TLS 均取自桥接返回的对应预设，非法域名或缺失预设在发送凭据前拒绝。
   LINUX DO Mail 使用 `mail.linux.do` 的 IMAP 993 / SMTP 465 隐式 TLS，
   完整邮箱地址作为用户名，提示优先使用邮箱后台专用认证令牌，不使用论坛密码或论坛 OAuth。
3. **验证连接**：点击“验证并添加”后等待现有 `AddAccount`，该调用验证 IMAP/SMTP、
   保存系统凭据与账号，并尝试安排首次同步；不新建 Probe 或拆分后端接口。
   等待期间禁用配置和重复提交，失败后回到配置并聚焦安全错误提示。
4. **同步邮件**：账号创建成功后展示后台同步安排结果，清空并移除表单密码，刷新工作台。
   不再立即关闭，点击“完成”才返回邮箱；关闭弹窗不会中断应用运行期间的后台同步。
   此步骤不展示虚构百分比，不表示历史邮件已全部同步，实际结果在邮箱中查看。
   若首次安排失败，明确账号已添加、稍后可在邮箱中重试，不回到创建流程重复添加。
   排队返回 BUSY 表示已有同步任务，不作为启动失败处理。

### 同一服务商批量添加

- 预设从首个账号开始就使用“当前编辑 · 账号 1”卡片；点击“添加同服务商账号”增加下一项，
  当前项收成摘要，新项原位展开并聚焦邮箱。服务商只选择一次，不支持混合品牌服务商队列；
  同一“网易邮箱”批次允许混合 163 和 126，每行分别使用自己的端点、邮箱和授权码。
  每项独立填写邮箱、可选名称和密码，单批最多 10 个；预设仍不显示协议配置。
- 始终只展开一个可编辑面板，切回旧账号时在它原来的位置展开，其他项仍按账号顺序显示摘要，
  不把当前项移到末尾。摘要展示邮箱、可选名称和“已填写 · 待验证”/“待完善”等状态；
  未填写项也有“点击展开填写”和编辑入口，不把本地完整性当作认证成功。
- 摘要是原生按钮，支持点击、Enter/Space 切换；折叠字段仍挂载并参与校验，切换不丢凭据。
  提交优先定位当前面板错误；若错误在折叠账号或点击错误摘要链接，先展开原位置再精确聚焦。
  编辑卡片用主题细边框和轻阴影，新增入口为全宽轻虚线，不使用黑色粗边。
- 自定义批量共用上方的服务器、端口、TLS 和凭据复用策略；每个账号仍有独立的收发信用户名/密码。
  自定义单账号保留完整端点表单；需要不同服务器配置时应分批添加，已成功账号不会因后续修改而变化。
- 桌面下预设凭据按紧凑列排布，小窗口改为单列；新增账号自动聚焦该行邮箱。
  桌面底部展示待验证数量，小窗口隐藏辅助数量以保留主操作空间。
  提交前可移除账号，但不能移除最后一项；移除后聚焦存活的可见编辑区，
  删回一个预设账号仍保持同一卡片。开始处理后冻结增删，成功/待核对项锁定，失败项可修改。
- 一键提交后按顺序调用现有 AddAccount，避免后端互斥导致并行 BUSY。
  当前批内邮箱不区分大小写去重，不改实际登录邮箱大小写；只处理合法且未添加的项目。
- 每个成功账号独立保存并刷新工作台，开始自己的后台同步；失败不回滚成功账号，也不阻断后项。
  部分失败回到第二步并聚焦摘要，逐行显示安全错误，重试不会再提交成功项。
- 超时、保存或桥接结果不确定的项目标记“待核对”，清空其密码并禁止直接再次提交，
  以免重复创建；请先在邮箱核对。不能把这些情况当作确定未保存或已成功。
- 批量等待时只展示进度/结果元数据，不展示密码输入；全部明确添加成功后进入第四步。
  同步安排失败仍算账号已添加，单独显示安排错误，不通过重复添加账号来重试同步。
- 关闭弹窗会取消当前等待、停止未开始项，已保存账号及其后台同步保留；
  正在处理的账号可能已提交，请在邮箱核对，不能承诺关闭会撤销创建。
- 草稿和密码仅在本轮内存中，不写入浏览器存储或日志；移除/返回清理秘密，
  成功后清空对应密码。实际凭据持久化仍由原后端系统凭据存储处理。

### 通用交互与边界

- 支持返回选择；返回立即清空两侧密码，邮箱/名称只在本轮弹窗内保留；
  重新选卡片会重置服务器配置，不把旧凭据带入新服务商。验证中禁止返回或重复提交；
  已创建账号不能重复提交；批量失败项按上节规则修改重试，成功项不受影响。
- 邮箱快捷入口会将地址带入配置邮箱及收发信用户名；保留手动卡片入口，空邮箱不阻止手选。
- 选择页标题下不再重复显示自动识别说明，直接展示邮箱标签和输入；
  输入下方动态识别状态及配置页的登录说明保留。
- 账号文本输入和选择器采用细边框、统一 field 圆角，聚焦时以主题强调色与轻光晕替代硬黑轮廓；
  不改变控件尺寸。键盘焦点保持可辨，强制颜色模式使用系统高对比轮廓，
  减少动效时关闭过渡；不覆盖复选框和按钮的原有焦点。
- 账号表单提交使用原生 ValidityState 判定必填、邮箱格式、数值范围和长度，但由应用呈现错误，
  不调用 reportValidity，也不显示浏览器原生校验气泡。required/type/min/max/maxLength 与后端校验保留，
  无效信息不能触发添加请求。
- 单处问题仅在字段下方显示提示，使用轻红边和 aria-invalid / aria-describedby；
  多处问题额外显示内容区顶部摘要及到对应字段的链接。错误随文档流排版，不覆盖相邻账号或控件。
  错误节点提交到 DOM 后聚焦首个无效字段，修正内容、移除账号或切换字段时清理关联错误；
  标签名称不混入错误文字，动态邮箱识别描述保留，错误提示不包含原始输入或密码。
- 选择页不再显示原密码存储说明，也不保留空底栏；凭据存储方式未改变。
- 选择页提供加载、失败与空列表状态及重试，不用静态假数据绕过桌面服务。
- 卡片为原生按钮，名称与说明支持读屏；Tab/Enter/Space 可操作，进入配置聚焦邮箱，
  返回/重试聚焦步骤标题，验证/同步阶段聚焦阶段标题，Esc 关闭后恢复原入口焦点。
- 样式使用现有 Token，支持明暗主题、中英文与小窗口单列卡片；
  右侧内容和紧凑左侧进度按需独立滚动，头部与底部保持可见，外框不产生第二条滚动条。
- 外框与设置、撰写共用 [DialogFrame](../components/dialog.md)，桌面基准 900×580，
  小窗口按视口收缩；四阶段保持同一长宽，内容过长时在内部滚动。
- 左侧进度复用设置导航的宽度 Token（桌面 196px，紧凑视口 124px），通过有序列表和
  `aria-current="step"` 表示当前步骤；选择服务商后显示勾选与服务商名称，仅表示选择完成，
  不表示账号认证/添加成功。第三步只在 AddAccount 成功后标为完成，第四步显示后台安排结果，
  不冒充全部邮件同步完成。进度不提供跳过步骤的按钮，推进时紧凑左栏自动露出当前阶段。
- 当前步骤使用单个持续存在的背景指示器，在步骤间纵向移动并适配行高；
  由 `--motion-step-progress`（360ms）与主题缓动控制。推进、返回及验证失败回退
  从当前插值位置接续，快速反向不重置或重建背景；不增加业务等待时间。
  尺寸/内容变化由 ResizeObserver 跟随，语言/窗口变化重新测量；
  卸载清理 observer、监听和 RAF。减少动效时直接定位，强制颜色模式保留系统选中边界。
- 右侧标题和关闭入口固定，内容独立滚动，配置步骤底部保留返回/验证按钮；
  第四步只保留完成入口；右侧滚动不移动左栏，小窗口维持紧凑左右列并将服务商卡片改为单列。
- Gmail 卡片与配置页明确使用应用专用密码，区分于 Google 登录密码，不展示 OAuth 注册要求或授权入口。
  未新增 Outlook/iCloud、OAuth 浏览器授权、服务器自动发现、协议级细分进度或同步百分比。
- 实现与验证见 [TASK-0039](../../07-tasks/archive/2026/10/TASK-0039-account-provider-selection.md)、
  [TASK-0041](../../07-tasks/archive/2026/10/TASK-0041-account-provider-detection.md)、

以下三步方案与接口示例为历史产品目标，尚未全部实现；与当前四步交互不一致的部分不作为现有能力。

## 目标与入口

入口：首次启动引导、侧栏"添加账号"、设置 → 账号 → 添加。
目标：常见邮箱 3 步内完成，异常时能被准确告知原因。

## 历史三步方案（非当前交互，单窗口模态 480×自适应）

```
步骤一  步骤二  步骤三
●───────○───────○

第 1 步：识别邮箱
  ┌────────────────────────────────┐
  │ 你的邮箱地址                    │
  │ [name@example.com            ] │
  │ 常见服务商：Gmail · Outlook · QQ · 163 · iCloud │
  └────────────────────────────────┘
            [取消]  [下一步]

第 2 步：登录（取决于 authKind）
  预设服务商 -> 主机/端口只读展示（可展开"高级设置"修改）
  密码方式： [密码 / 应用专用密码]  [显示]
  OAuth 方式： [使用浏览器授权]（点击后显示"等待浏览器授权…"）

第 3 步：校验中 / 结果
  分阶段进度：● 连接服务器  ● 身份验证  ○ 读取文件夹
  失败 -> 错误标题 + 建议 + [返回修改] [查看详情 ▾]
```

## 区域与元素

| 元素 | 规格 |
| --- | --- |
| 步骤指示 | 圆点 + 连接线，当前步 accent 填充；已完成步可点击回退 |
| 邮箱输入 | `Input kind=text`，域名合法即启用"下一步"（不要求格式完美，允许带显示名） |
| 服务商快捷入口 | 5 个 chip，点击预填域名 |
| 高级设置 | 折叠区：IMAP/SMTP 主机、端口、加密方式（SSL/STARTTLS/无） |
| 密码字段 | `kind=password`，附"去哪找应用专用密码"的帮助链接 |
| 校验进度 | 三阶段，每阶段 10s 超时；阶段失败即终止并显示原因 |
| 错误区 | 标题（用户语言）+ 建议动作 + 可展开 technical detail |
| 底部按钮 | 次要在左，主操作在右；校验中主按钮 loading 且不可点 |

## 交互与状态

| 场景 | 行为 |
| --- | --- |
| 域名命中预设 | 自动填充并显示"已识别：Gmail"，可展开高级设置覆盖 |
| 未命中预设 | 直接展示手动参数表单，必填项标注 |
| 校验成功 | 自动进入完成态：`✓ 已添加 ACCOUNT_LABEL`，1 秒后关闭并跳转收件箱 |
| 密码错误 | 停留在第 2 步，密码框清空并聚焦，显示 `AUTH_INVALID` 文案 |
| 需要 OAuth | 隐藏密码字段，显示授权按钮；点击后打开系统浏览器 |
| 超时 | 显示 `NET_TIMEOUT` + 建议（端口/网络/防火墙） |
| 服务商禁用 IMAP | 显示开启指引（图文步骤链接） |
| 取消 | 二次确认（若已输入内容） |

## 键盘操作

- `Enter` 进入下一步 / 提交；`Esc` 取消（带确认）。
- 焦点自动落在邮箱输入框。

## 数据依赖

`Account.Probe`（只校验）、`Account.Create`（落库 + 存凭据 + 触发同步）。

## 验收要点

- [ ] 输入 `name@gmail.com` 后不需手填任何服务器参数即可完成。
- [ ] 任一阶段失败时，用户能看懂"是密码、网络还是服务商设置"的问题。
- [ ] 校验中界面不冻结，可取消（取消后不落库）。
- [ ] 密码字段不被写入任何持久化存储（含 localStorage）。
- [ ] 深色主题下错误态与进度态清晰可辨。
