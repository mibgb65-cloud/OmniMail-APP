# TASK-0048 邮件正文与图片安全完整展示

> 状态：已完成
> 负责人：@Codex | 创建：2026-10-30 | 优先级：P1
> 关联：FR-02-9 / FEAT-0007 / ADR-0005（草稿）

## 需求与目标

用户已评审通过 TASK-0047，并提出下一任务：右侧内容区应展示完整邮件内容，
不能只有纯文本，图片等邮件内容也需要显示。

目标是保留并展示邮件 HTML 正文、基本排版、表格、链接及正文内嵌图片，
同时维持邮件不可信输入的隔离与隐私边界。不将“完整展示”理解为允许邮件执行脚本或任意访问网络。

## 当前事实

- `mailnet/mime.go` 将 HTML 转为纯文本回退，没有保留原 HTML。
- `domain.DecodedMail` 仅有 `Text` 和附件，`MailDetail` 仅向前端提供纯文本 `Body`。
- MIME 的非文本 inline part 被缓存为普通附件，但 Content-ID 未保存，
  正文 `cid:` 引用无法对应到图片。
- 数据库 `mail_message` 仅有 `body_text`，`mail_attachment` 没有 Content-ID。
  现有 `service.Message` 对已缓存邮件直接返回，不会重新获取原 HTML。
- `MailContent.tsx` 使用文本节点显示正文，这是现有安全降级，不是完整渲染。
- FEAT-0007 与 ADR-0005 描述白名单清洗、沙箱 iframe、CSP 和远程图片拦截，
  但文档仍为草稿，不能将其描述为已经实施。
- 当前已有 TASK-0047 的未提交改动及运行中的桌面开发实例；必须保留，
  新任务涉及的共享文件按差异块区分，不自动暂存、提交、清理或终止无关进程。

## 范围

### 包含

- MIME 解析同时保留 HTML 和纯文本，保存内嵌图片 Content-ID，继续执行邮件/文本/附件大小边界。
- 增量保存 HTML、正文缓存版本与 Content-ID，不删除原有正文、附件或账号数据。
- 对旧版纯文本缓存提供有界的原文重新获取路径；未联网或账号已断开时保留原缓存并明确提示，
  不通过清空缓存伪装升级成功。
- Go 侧白名单清洗；前端隔离 iframe + CSP；保留可安全呈现的排版和内容。
- 本地内嵌图片优先显示；远程图片默认拦截，明确提示并由用户按当前邮件主动加载，
  不默默记忆全局信任、不自动发起第三方图片/字体/CSS请求。
- 外链仅允许校验后的 HTTP/HTTPS/mailto，由父应用交系统处理；
  邮件内部禁止脚本、事件处理器、表单、嵌套 iframe、危险协议及访问桌面绑定。
- 纯文本邮件保持可读、可复制；附件下载保留；中英文、安全提示及现有主题适配。

### 不包含

- 执行脚本、交互式 HTML 表单、内嵌视频/音频、任意 SVG/HTML 附件执行。
- 远程图片代理、全局自动信任、外部字体或样式表自动加载。
- 邮件编辑、回复/转发、附件发送、原始 EML 导出或与本任务无关的整页重构。
- 未经用户授权使用真实账号、采集真实邮件内容或在日志/测试夹具中保存真实邮件。

## 方案与取舍

- 不把原始邮件通过 `dangerouslySetInnerHTML` 注入主应用；即便 HTML 看似安全，也不能访问主应用样式与桥接上下文。
- 推荐使用 Go 侧成熟的 `bluemonday` 白名单清洗库，结合安全样式过滤与现有 `x/net/html`，
  避免为绕过依赖审批自行拼凑正则 HTML 清洗器。
- 采用新增字段的数据库迁移保存原 HTML、缓存版本与 Content-ID；维持现有纯文本数据，
  不在 `body_text` 中塞入不兼容 JSON 或 HTML 来规避迁移。
- 清洗输出与原文的存储边界、内嵌图片的类型/总量限制、旧缓存重取触发方式，
  在实施前继续结合现有仓储和服务测试细化，不能导致离线内容丢失或反复请求服务器。
- 远程图片授权限定当前邮件；安全隔离无法保证所有营销邮件像网页原样渲染，
  外部 CSS、字体、脚本依赖的布局允许安全降级并如实披露。

## 实现结果

- MIME/领域：新增原 HTML 与 Content-ID 保留，正文预算按解码前的完整 HTML 文本累计，
  不再因剥离标签而让多段 HTML 绕过限额。邮件资源类型、CID 长度/控制字符有边界校验。
- 仓储：新增迁移 `0003_rich_mail.sql`，保存 `body_html/body_version/content_id`，
  沿用事务及迁移前备份。旧文本、账号、附件不删除；新版缓存版本为 1，旧缓存保持 0。
- 安全：独立 `internal/mailrender` 使用成熟白名单与 CSS 值处理器；
  原 HTML `json:"-"` 不出 IPC，只返回清洗且资源惰性的 `bodyHtml`。
  内嵌图校验实际 PNG/JPEG/GIF/WebP、单图大小/尺寸与总像素预算；超限图片降级提示。
- 服务/桥接：增加 `RefreshMessage`，旧缓存由用户显式重取，失败仍可阅读原缓存；
  CID 只从当前详情的附件列表解析，忽略本地路径及其他邮件资源，不提供任意 Go 网络代理。
  Wails 绑定已按项目锁定工具生成并审阅，无手改绑定。
- 阅读器：`MailBody` + inert 模板资源激活 + `mailFrame`，固定无脚本 sandbox、无 referrer 和严格 CSP，
  图片/链接处理在主应用控制下进行；纯文本安全回退，图片不可用/链接失败有明确反馈。
  邮件内部底板保持浅色，避免反色破坏原邮件设计，外围继续跟随主题。
- 设置：`SettingsMailImages` 接入通用设置；三档默认 inline，本机偏好键
  `omnimail.mailImages`；即时联动、非法值回退、存储失败保留会话并提示。
  临时“仅本封显示”在切换邮件或设置时清除，不自动信任其他邮件。
- 回归：新增 MIME、迁移、仓储往返/失败不丢缓存、服务/CID 隔离、恶意 HTML、
  图像格式/像素预算、iframe/外链、偏好持久化与存储失败测试。
  保留 iframe `title` 的文档无障碍名称，统一 Tooltip 回归仅对此语义明确豁免；
  其他原生控件继续禁止 `title`。
- 文档：更新 FEAT-0007、ADR-0005、主界面与详情页的当前实现说明及安全降级范围。
