# TASK-0057 未读筛选会话保持列表位置

> 状态：已完成
> 负责人：@Codex | 创建：2026-10-31 | 优先级：P1

## 用户需求与范围

- 未读筛选开启后，实际阅读仍自动标记已读并回写服务商，但读过的邮件留在本轮列表中；连续读多封也不能自动移出。
- 用户主动点击同步或切换筛选条件时重新计算列表；账号/分类切换创建新的视图，不串用其他范围的快照。
- 包含：未读筛选成员快照、实时状态展示、列表/工具栏计数与前后导航一致性、分页及回归测试。
- 不包含：停止已读回写、伪造未读状态、修改数据库/协议/同步后端、修复其他未授权问题、自动提交或推送。

## 初始事实与方案

- 初始工作树存在 TASK-0056 的未提交 Gmail 同步修复；全部保留，不混入本任务代码。
- `MailList` 和 `MailToolbar` 分别调用 `selectMailView`，直接用实时 `read` 状态过滤。
  自动已读更新后立即不满足条件，导致选中条目消失，工具栏前后导航也找不到当前项。
- 方案比较：暂停列表刷新会让计数/已读/同步状态过时；把 `read` 假装成 false 会破坏服务商状态。
  采用仅在未读筛选开启时保留成员 ID 的会话快照，行内容和已读/星标状态继续读取实时数据。
- 内部 refresh、3 秒账号轮询和后台同步不得重算既有成员；显式同步、搜索/筛选或账号/分类变化重建。
  排序只改变本轮成员顺序，不等同重新筛选，避免用户仅切换时间顺序就丢失已读位置。
  用户加载下一页时仅扩展新匹配成员，既有已读成员仍保留；明确归档/删除或服务端真正移除的条目仍可移出，不显示幽灵邮件。
- 第一实施步不超过 10 文件/600 行：视图 Hook 和测试、控制器接线、分页 Promise 返回、
  列表/工具栏共享视图及测试夹具适配。第二步更新受影响文档、完整门禁和交付记录。
- 细化为只冻结本轮已加载 ID 的未读判定，不复制/冻结邮件对象；新加载页仍按首次出现时的状态扩展集合。
  分页元数据增加已加载页数以区分用户加载下一页和后台刷新，不必改分页 Promise 或后端查询。
  后台新到邮件不会悄悄混入本轮未读筛选，现有加载范围的成员在内部重验时保持，真实状态与数据仍更新。
- 主动同步建立一个有限的刷新窗口：在该次同步状态变化、相关账号停止同步且本地列表重验完成前允许加入新未读，
  但不重新判定既有成员；窗口结束后继续冻结。避免“点同步却要再点一次才能看到新邮件”，也避免后台同步永久解冻筛选。

## 实现结果

- 新增 `useMailView` 保存已加载 ID 的未读判定，不复制正文或伪造 read；实时摘要仍驱动已读样式、未读统计、星标与动作。
- `useMail` 输出单一 `visibleMessages` 给列表和工具栏，计数、选中与前后导航不再分别重新筛掉已读成员。
- 分页快照携带已加载页数，区分下一页扩展和同页后台更新；新到未读不悄悄混入本轮，显式同步/条件改变后可出现。
- 主动同步创建一次有限的刷新窗口，在下一次成功账号轮询确认同步结束且本地重验完成后关闭；
  同步中阅读过的既有成员仍保留，极快完成且时间戳不变也不会永久解冻筛选。
- 搜索/未读/附件条件、账号/分类切换开启新快照；时间排序只重排，不推翻本轮身份；真正归档/删除仍移除。
- 未修改已读桥接、后端、数据库、邮件缓存、认证、安全策略或依赖。现有 TASK-0056 改动保留。
