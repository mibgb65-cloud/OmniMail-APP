# TASK-0030 多服务商账号与邮件存储基础

> 状态：已完成 | 完成：2026-10-27
> 负责人：@Codex | 创建：2026-10-27 | 优先级：P0
> 关联：FR-01 / FR-02 / FR-03 / ADR-0002 / ADR-0004

## 需求与目标

用户同意开始实现上一轮讨论的本地存储方案：同一服务商可以添加多个账号，
支持 Gmail、网易、QQ 等预设和自定义 IMAP/SMTP，后续新增预设不应要求数据库迁移。

## 范围

### 包含

- 先落实设计、实体边界、约束、服务商扩展约定及分步验收。
- SQLite 驱动确认后，实现数据库初始化、版本迁移、账号与连接配置存储。
- 账号、连接配置与敏感凭据分离；明确凭据补偿和保留本地数据的边界。
- 真实数据库测试与必要的应用生命周期接入。

### 不包含

- 本轮不实现真实 IMAP/SMTP 收发信、OAuth 浏览器授权、邮件同步和邮件 UI。
- 不把连接配置保存描述为已通过服务器连通性或认证校验。
- 不实施未确认的邮件静态加密、自动备份调度、云端同步或数据库拆分。
- 邮件实例、正文、附件等先完成设计，不提前建立尚无用例的生产数据表。

## 分析

- 当前 `desktop/internal` 只有启动、配置、日志和版本绑定等骨架；没有数据库驱动和持久化实现。
- ADR-0002 已确定 SQLite + 文件系统，驱动选型仍未决；新增依赖须先说明影响并取得确认。
- 现有 `database/schema.md` 是草稿，缺少连接配置，Message-ID 唯一约束及服务器实例设计需要修订；
  尚无已发布数据库需要兼容迁移。
- 服务商预设随应用内置，账号保存实际连接配置快照；增加预设无需增加业务表或扩展数据库枚举。
- 工作树存在大量其他任务改动，包括 TASK-0028、TASK-0029；不得覆盖、暂存或认领其内容。

## 验收标准

- [x] 服务商、账号、连接、文件夹及服务器邮件实例的设计边界明确，新增服务商有单一预设扩展约定。
- [x] 同一服务商可保存多个账号；内置预设更新不会改写已有账号的连接快照。
- [x] IMAP 和 SMTP 可分别配置主机、端口、用户名、认证类型和凭据引用。
- [x] 非法输入不落库，账号及连接配置原子写入；业务数据库不保存密码或令牌。
- [x] 数据库重开后数据可读，外键及唯一约束生效；迁移校验失败时不继续启动。
- [x] 断开保留账号及连接、清除仅影响目标账号；邮件和附件清理待后续建表后另验收。
- [x] 实际运行完整 verify，并记录失败、跳过和未实现部分。

## 风险与依赖

- 新增 SQLite Go 驱动已获本轮继续实施授权；需运行完整 verify 并审阅必要的依赖变化。
- 推荐评估 `modernc.org/sqlite`（纯 Go），减少 CGO 工具链耦合；许可证、版本、维护情况、
  编译耗时和产物体积须在依赖评审时核对，不能预先宣称满足安装包指标。
- 实施版本：`v1.61.0`，模块元数据发布时间为 2026-10-21，要求 Go 1.26.0，与当前工程匹配。
  官方版本 LICENSE 为 BSD-3-Clause 条款，发布二进制需附许可声明。
  其模块最低版本要求会涉及现有间接依赖更新，包括 `golang.org/x/sys` 0.48.0 → 0.49.0、
  `github.com/mattn/go-isatty` 0.0.20 → 0.0.24、`github.com/dustin/go-humanize` 1.0.1 → 1.1.0；
  实际依赖还包括 `x/crypto`、`x/mod`、`x/net`、`x/sync`、`x/term`、`x/text`、`x/tools`
  的必要版本选择变化及 `go-strftime` 等；完整 verify 已通过。
  已核对账号仓储运行依赖清单并保存驱动原许可，发布前仍需完整传递依赖及资产许可审计。
- 系统凭据存储尚未实现；仅有 `credential_ref` 不代表凭据已经安全保存。
- 正文、附件和 SQLite 静态加密未实现；服务商参数与实际认证能力需要网络集成阶段验证。

## 实现结果

- 新增 `database/account-storage.md`：明确服务商预设扩展、账号及收发信连接字段、邮件实例身份、
  同步代次、正文/附件下载状态、凭据与文件补偿及分阶段验收。
- 数据库入口增加当前实施进度说明，明确旧 Schema 是草稿；当前任务索引只追加 TASK-0030。
- 前一轮只完成设计，没有修改依赖或执行迁移；下述为本轮实际实现，不追溯覆盖此前事实。
- 新增领域账号/连接模型、类型化枚举、严格输入校验及仓储/凭据边界接口。新增服务商只需扩展
  `ProviderPresets()`；已有 Gmail、QQ、网易 163、网易 126、自定义预设，未知历史代码仍可读取。
- 接入 `modernc.org/sqlite v1.61.0`。与实施前的临时基线对比，go.mod 为 19 行新增/11 行删除，
  go.sum 为 56 行新增/21 行删除；包含必要的间接依赖更新与 tidy 整理，不升级 Wails 或前端依赖。
- 新增本地 SQLite 打开、WAL/连接级外键、身份校验、事务迁移、校验和、升级前 `VACUUM INTO`
  及账号/连接表；未知、较新或历史异常数据库失败关闭，不自动修复或删除用户库。
- 仓储支持原子创建/更新、完整列表/读取、断开保留、目标账号级联删除及移除后未引用凭据识别。
  存储错误保留可判别错误链，但不直接输出底层路径、SQL、参数或数据库异常文本。
- 应用启动初始化数据库与日志，关闭回调和退出共用幂等收尾；数据库失败时释放日志句柄。
- 更新实际 Schema 与迁移文档，撤下旧混合 shell 覆盖恢复示例，保留历史草稿但明确不可直接执行。
- 没有新 Wails 账号 API 或 UI，没有 OS 凭据实际写入/删除、网络认证、邮件数据表或真实收发信。
  凭据引用回收结果只是事务提交时的判定，后续服务层仍须处理串行化与失败补偿。
