# TASK-0049 邮件链接安全交互、同步提示与星标闭环

> 状态：已完成
> 负责人：@Codex | 创建：2026-10-30 | 优先级：P1

## 本轮需求

1. 优化邮件链接原生黑色悬浮提示。
2. 点击邮件链接时先弹出网站安全提醒，由用户确认后再交系统打开。
3. 移除邮件列表顶部的普通后台同步状态，将其呈现在工具栏同步按钮。
4. 核对并保证邮件正文数据库持久保存，不把内存或临时缓存冒充数据库内容。
5. 按上下文将用户“新表邮件”理解为星标邮件，补齐标星/取消与星标分类刷新。

## 范围与事实

- 工作树已有 TASK-0047/0048 未提交变更，本轮保留；不得覆盖、批量暂存或自动提交。
- 正文当前实际保存于 SQLite `mail_message.body_text/body_html`，
  附件/内嵌图是持久文件加数据库引用，并非仅内存缓存。新增关闭/重开数据库的往返测试，
  修正文案；不擅自改成全量自动下载、删除旧缓存或再次迁移。
- 黑色链接提示来自 iframe 链接 `title`；当前统一 Tooltip 只监听主文档。
  保留无脚本隔离，为受控 iframe 接入统一提示、跨文档位置与键盘事件。
- 当前链接直接调 `openMailLink`，新增统一 DialogFrame 确认框，显示实际目标并提示自行确认安全；
  取消、Esc、切换邮件不得触发系统打开，不提供“永久信任”或伪造安全认证。
- 当前列表将 running/partial 作为普通信息条；只迁移此类同步进度，保留错误、
  重授权、账号断开及无账号等可操作提示，不以移动位置为由隐瞒失败。
- 已有 `is_starred` 和星标分类读取，但没有修改入口。沿用 IMAP `\\Flagged` 语义：
  服务器确认后更新本地数据库，失败不伪造成功；不新增离线操作队列。

## 追加修正：同步按钮悬停配色（2026-10-30）

- 用户反馈：同步按钮悬停时出现深色底，但文字/图标仍为灰色，观感异常。
- 原因：局部 `.sync-button` 没有声明 hover，命中全局主按钮
  `button:hover:not(:disabled)` 的强调背景，却保留局部次要文字色。
- 本轮计划：先用实际组件的浏览器断言复现配色失败，再仅补同步按钮的主题 Token 悬停覆盖，
  使用柔和底色和主文字色，保持禁用/同步中/键盘焦点、尺寸及 Tooltip 行为；
  不改全局按钮规则，不改同步逻辑，不覆盖此前任务的未提交改动。
- 验证计划：浅深色 idle/hover/busy、对比度、尺寸稳定、键盘焦点和减少动态偏好；
  CSS 定向格式检查与相关前端组件回归。纯局部样式不重复全量 Go/桌面构建，
  不将定向检查描述为本轮完整 verify。
- 实际结果：仅在 `MailToolbar.module.css` 增加同步按钮专属 hover（selected 底色 +
  primary 文本色），辅以既有时长 Token 的轻量颜色过渡；没有更改同步行为、Tooltip 或全局按钮规则。
- 失败证据：`node desktop/.task/t49-sync-hover-check.cjs` 修复前退出 1，
  浅色悬停为背景 `rgb(65,65,70)`、文字 `rgb(104,104,111)`，复现截图中的主按钮深底/灰字冲突。
- 修复后同一浏览器检查通过：浅色背景 `rgb(238,238,240)` / 文字 `rgb(32,32,35)`，
  对比度约 14.02；深色背景 `rgb(52,52,60)` / 文字 `rgb(239,239,242)`，
  对比度约 10.75。悬停尺寸无变化，同步中禁用态保持透明，键盘焦点和减少动态效果均通过。
- 定向验证：`npx prettier --check src/app/MailToolbar.module.css` 通过；
  `npm test -- src/app/MailContent.test.tsx src/app/App.test.tsx src/components/Tooltip/TooltipHost.test.tsx`
