## 用户需求与范围
- 在“我的邮箱”切换账号时，右侧邮件列表不能空白闪烁；加载时使用与详情一致的骨架流光，
  数据就绪后从上到下依次显示邮件行。
- 保留滚动边缘透明羽化、无限追加、键盘与点击交互、错误重试、空态及减少动态效果。
- 不修改服务端协议、数据库或邮件收发，不增加动画依赖，不自动提交/推送。

## 分析与取舍
- `useMailList` 已用 scope 和 AbortController 隔离旧请求，但切换时立即清空邮件；
  原列表只有底部“正在读取”文字，快速读取也会直接从空白跳到完整列表。
- 详情已有约 280ms 最短骨架和原生 Web Animations API 的 320ms/有界 stagger 入场。
  复用其骨架 CSS 流光、颜色和入场节奏，单独采用邮件行占位，避免把详情封面布局照搬进窄列表。
- 每个 `listKey` 挂载独立过渡实例；首批等待与最短骨架并行，
  不把分页追加、账号轮询、自动已读或筛选刷新误当账号切换。
- 仅首屏有界邮件行动画，滚动/聚焦/点击及减少动态效果可立即取消到最终样式；
  动画不承担业务就绪，不使长列表逐行等待数秒。
- 工作树有 TASK-0061～0068 的既有改动，全部保留；混合文件只改本次片段。

## 实现结果
- `MailList` 按 `listKey` 挂载独立的 ScopedMailList；新增 `useMailListTransition`，
  仅首批无快照期间进入骨架，最短等待与读取并行。错误不受计时器阻挡；
  请求结果的旧 scope/Abort 隔离继续由原 `useMailList` 负责，不改后端或请求协议。
- `MailListSkeleton` 复用 `MailSkeleton.module.css` 的流光、主题色和减少动态样式，
  独立占位发件人、日期和两行主题；满高但不让真实滚动区域被骨架内容撑长。
- 复用 `revealMailPage` 的原生 WAAPI 入场；可选视口参数限定可见邮件行，
  原详情默认行为保持。仅首屏最多 18 个目标，延迟递增、总时长有界，
  滚动/点击/聚焦/减少动态均可取消到最终状态，卸载释放监听与动画。
- 背景加载仍保留原邮件，追加与同范围数据更新不会重建视口/重播整列；
  ScrollArea 的透明边缘羽化、独立轨道与无限加载条件继续保留。
- 无新依赖、无新语言键、无数据库/邮件行为变化；更新收件箱和变更日志。
