## 需求与范围

- 移除 Gmail 配置页顶部的填写说明，保留下方应用专用密码安全提示。
- 用户明确要求同一服务商下添加多个账号，不是混合服务商队列。
- 服务商只选择一次，每个账号分别输入邮箱、可选名称和密码；预设共用 Providers 端点，
  自定义共用服务器/TLS/发信凭据复用策略，但每个账号有自己的用户名和密码。
- 一批最多 10 个，提交前检查批内邮箱重复（不区分大小写）；真实请求仍由后端最终校验。
- 批量按顺序验证添加，逐项显示结果；成功项不可重复提交，失败项可修改后重试。
- 成功账号不因其他账号失败或关闭而回滚；关闭取消当前等待并停止后续提交，已在后端提交的结果需在邮箱核对。
- 不新增后端批量接口、依赖、数据库或凭据存储方案，不混入其他服务商模式。

## 分析与取舍

- `Mail.AddAccount` 使用 actions.TryLock，直接 Promise.all 会产生 BUSY；采用前端串行批处理，
  每个成功账号沿用原系统凭据存储及后台首次同步安排，不额外 QueueSync。
- 保留现有单账号流程；只有用户点击“添加同服务商账号”才切换批量编辑。
- 新账号凭据只在本轮内存中；移除/返回清理秘密，成功后清空对应密码，结果仅保存安全元数据。
- 部分失败不再走全批重复创建；已成功项锁定，重试只处理未添加项。自定义元数据改变仅影响待添加项。
- 超时、桥接/保存不确定等不能证明未落库，标为待核对并清空秘密，不直接重试，避免重复创建；
  关闭后请在邮箱核对。明确的认证/输入错误仍可修改后重试。
- 原有 TASK-0041/0042/0043 未提交成果全部保留；本任务文件首次创建为流程引导例外。
