# TASK-0005 建立统一 AI 开发入口与任务工作流

> 状态：待评审 | 负责人：@Codex | 创建：2026-10-25 | 最后更新：2026-10-25 | 优先级：P1
> 关联：用户要求按提供的 AGENTS.md 示例补齐 OmniMail 的正确开发流程

## 需求与目标

在任何其他项目文件修改前创建本记录。新增仓库根目录 AI 入口，使后续开发遵循可追溯的
“需求 → 任务记录 → 分析计划 → 实现 → 验证 → 文档 → Git 处置 → 评审归档”流程。

## 范围

### 包含

- 根目录 `AGENTS.md`，引用真实存在的产品、架构、开发和任务文档。
- 统一 AI 协作规范、任务模板、状态及完成条件。
- 基于锁定的 Wails v3 Task 工具建立 `verify` 聚合质量门禁，保留现有启动和构建入口。
- 更新相关入口、索引及本任务的实际实现和验证记录。

### 不包含

- 不调整应用界面、邮件功能、技术栈、依赖或数据格式。
- 不创建 CI 流水线，不假称已有 CI；TASK-0003 保持独立。
- 不补造此前 UI 调整的事前任务记录、验证结果或提交号。
- 不提交、推送、重置、暂存或清理用户已有的工作树改动。

## 分析

- 当前根目录没有 AGENTS.md，AI 规则分散在 `00-guidelines/ai-agent-rules.md`。
- 当前任务规范已有模板和归档目录，但未明确所有修改必须先建记录。
- 当前 `check` 与 `build` 分离，未定义 `verify`；Wails CLI 由 go.mod 锁定。
- 当前技术基线由 go.mod、frontend/package.json 和实际代码确定；ADR-0001 包含历史 v2 方案，不能照搬为现状。
- 当前分支为 main，HEAD 为 ee3d5d1；工作树有大量既有修改和未跟踪文件，必须保留。

## 实施计划

1. [x] 核对现有规范和任务状态，确定唯一事实来源及授权边界。
2. [x] 新增根目录 AGENTS.md，收敛工作流及读取入口。
3. [x] 更新任务模板、AI 规则和相关索引，明确未授权提交的处理方式。

5. [x] 核对链接、执行门禁并回填实际结果，交付评审。

分步文件范围：

- 第一阶段：AGENTS.md、AI 协作规范，建立统一流程入口。
- 第二阶段：任务管理规范、Taskfile，建立状态模板与可执行门禁；已完成 verify dry-run。
- 第三阶段：根 README、桌面文档索引、规范索引、当前任务索引、Git/代码/测试/构建说明，
  只修正与统一流程直接相关的入口、命令或授权表述，不迁移历史目录或改写其他任务正文。
- 最后在忽略目录 `.task/` 中验证格式检查失败/成功路径，再运行完整门禁和链接核对。

## 验收标准

- [x] 新进入仓库的 AI 能从根目录找到正确规范与命令。
- [x] 所有修改类任务先创建或复用任务记录；只读咨询无须建记录。
- [x] 任务记录包含分析、实施计划、实际结果、验证、Git 处置与遗留风险。
- [x] verify 按格式、静态检查、类型、测试、构建执行，任一阶段失败即失败。
- [x] 验证使用独立输出目录，已有 check/build/dev 入口继续可用。
- [x] 规则不指向虚构目录，不把计划功能、历史方案或未配置 CI 当成已实现。
- [x] 未经授权不执行 Git 提交或推送，不更改既有用户改动。

- 不涉及运行数据迁移；依赖现有 Go、Node/npm 和已锁定的 Wails 工具。
