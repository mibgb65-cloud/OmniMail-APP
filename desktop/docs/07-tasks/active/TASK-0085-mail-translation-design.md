## 用户需求与本轮范围
用户希望接入 B 站免费的 Index-Translate-35B-A3B，并询问怎样实现更好。
本轮核对官方 API、做一次非敏感样例连通性验证，并给出适配 OmniMail 的设计；
不上传真实邮件、不把设计或界面文案当成已实现翻译功能，不擅自开启自动云端翻译。

## 已核对事实（2026-11-01）
- 官方站点与 bilibili/Index-Translate 仓库明确提供免费公网 API，兼容 OpenAI。
- 官方 call_api.py 默认 model 为 Index-Translate-35B-A3B，
  endpoint 为 https://index-translate.bilibili.com/v1/chat/completions。
- 示例使用 Content-Type/User-Agent，不需要 Authorization/API Key；网页内模型别名不能替代公开 API 文档。
- 官方示例设置 chat_template_kwargs.enable_thinking=false，支持非流式与 SSE。
- 只用 “Hello, world!” 请求了一次，HTTP 200、finish_reason=stop、返回“你好，世界！”。
  没有读取用户邮箱或发送任何真实邮件。
- 未找到明确的 SLA、配额、长期免费及邮件数据保留承诺；不能从开源许可推导托管 API 隐私保证。
- 现有 MailReaderPage/MailBody 已分离正文与原始隔离 HTML，但没有邮件内容翻译。
  useTranslation 是界面国际化，不能与邮件翻译混为一谈。

- Go 负责授权、正文提取、HTTP、分片/限制、取消与成功缓存；前端纯文本渲染译文，支持原文切回。
- 沿用当前数据目录，新增小型翻译偏好和派生缓存，无数据库迁移、新依赖或新第三方服务。

  桥接/装配 → 工具栏、选择/授权窗、原文译文呈现 → 回归与完整 verify。

  成功缓存、取消/失败/截断安全，真实公开接口仅使用合成短文验证。

## 第二轮最终实现
- 新增 `domain/translation.go`，定义目标白名单、偏好/结果、错误与 provider/存储/阅读边界；
  `translationapi` 用 Go HTTP/JSON 直接调用固定 B 站 HTTPS 地址，不接受前端 URL、不发送 Key/Cookie、
  禁止重定向并限制连接、响应与输出。按官方配置禁用推理，要求 subject/body JSON，严格检查 stop 与字段完整性。
- 新增 Go 翻译服务：先校验 ID/目标/授权，再只读本地缓存标题/正文；
  HTML-only 本地提取、忽略脚本/样式/图片属性，不触发 IMAP 或外链图片请求。
  每进程一个有界任务，按段落切片，有整体超时/输入输出限制，取消/关闭应用会终止任务。
- 新增翻译偏好文件与派生缓存：授权默认关、目标默认简体中文，
  成功缓存按账号/邮件/标题正文摘要/目标/model/格式版本隔离；原子写入、严格 JSON/路径边界，
  128 条/16 MiB 限量，不写原文或不完整结果。缓存失败明确交付 warning，不让成功翻译消失。
- 注册 TranslationBridge Preferences/SetPreferences/Translate 并装配资源生命周期，
  退出先取消并等待翻译，再关闭邮件/SQLite；无新依赖或数据库迁移。
- 在用户指定的工具栏归档前增加图标按钮；禁用未选中/未完整缓存/撰写场景，
  弹窗提供 7 种目标语言、源自动识别说明及明确云端授权，可仅保存或撤销授权。
- 阅读页同时切换标题/正文，译文只作 React 纯文本，不执行模型标签；原 iframe 保持挂载，
  切回不重置原有图片授权/链接行为。附件、原邮件和星标目标不变。
- 翻译状态用选中 ID 和正文对象快照绑定；切换、刷新和撰写取消，迟到结果/错误不串邮件。
  确认窗也绑定打开时的快照，不会切换后对新目标自动弹窗或上传。
- 独立中英文 translation 命名空间，更新 AI 页过时的“不向 AI 服务发送邮件”说明，
  不宣称通用 AI 分析已接入；页面规范与提案已更新为真实实现边界。
