# TASK-0039 添加邮箱服务商卡片选择页

> 状态：进行中
> 负责人：@Codex | 创建：2026-10-28 | 优先级：P1
> 关联：TASK-0036 / FEAT-0001

## 需求与目标

点击添加邮箱后，首先展示服务商选择页，区分预设服务商与自定义服务商；
通过对应卡片进入所选服务商的具体配置与验证流程，不再直接堆叠完整参数表单。

## 范围

### 包含

- 在现有添加账号模态窗内实现“服务商选择 → 账号配置”两步流程。
- 根据真实 Providers 接口展示服务商卡片与自定义 IMAP/SMTP 入口。
- 配置页显示已选服务商，支持返回选择；预设沿用既有端点填充，自定义保留手动配置。
- 加载/失败/重试、键盘焦点、明暗主题、中文/英语与回归测试。

### 不包含

- 新增服务商、OAuth 注册客户端/登录能力、协议适配或后端接口变更。
- 改动邮件收发、凭据存储策略、其他弹窗、语言胶囊或已存在的其他任务成果。
- Git 提交、推送、分支切换和归档。

## 分析与取舍

- 当前 AccountDialog 在打开后立即呈现服务商 select 与全部 IMAP/SMTP 字段。
  useAccountForm 已负责 Providers 加载、端点预填、用户名同步与 AddAccount 调用。
- 真实预设在 `internal/domain/provider.go`，包含 Gmail、QQ、网易 163、
  网易 126、自定义 IMAP/SMTP；不会把草稿中的 Outlook/iCloud 展示为已实现入口。
- Gmail 仍只允许满足条件的应用专用密码接入，OAuth 未配置，保留并前置说明限制。
- 采用同一模态窗内分步，不新增路由/框架；选择页隐藏表单与验证提交，
  点卡片后再显示配置，不自动发起认证。
- 预设配置流程保留可编辑端点与原有验证，避免把服务商授权策略虚构为可用 OAuth；
  配置页聚焦邮箱，返回选择页聚焦步骤标题，卡片采用原生按钮。
- 将现有账号状态 Hook 单独提取，保留服务调用与验证 DTO，选择页单独组件和 CSS Module；
  添加两步进度说明，卡片使用中性主题 Token 与文字标识，不引入品牌图片或外部资源。
- 保留邮箱地址/账号名称等本轮内存状态；返回或更换服务商时清除服务器凭据，
  沿用原有服务商切换清理秘密的安全边界，不写浏览器存储。
- 工作树有 TASK-0038 的累计未提交改动，全部保留；
  共享 active 索引只追加 TASK-0039，不改写旧任务状态或已有代码。

- 提取 useAccountForm，保留原端点填充、邮箱/用户名同步及验证 DTO；
  服务商初始不选中，只有选择卡片后渲染表单和验证按钮。
- 新增 ProviderSelection 与账号专用 CSS Module，后端列表驱动预设/自定义分区；
  两步进度、已选服务商标题、返回、原生键盘交互与安全提示已接入。
- 返回即时清除两套密码；提交使用请求 ref 防止重复提交，关闭后忽略晚到结果；
  服务商加载可重试、可取消，空列表不构造虚假的可用入口。
- 颜色均引用现有 Token，卡片使用中性文字标识；Gmail OAuth 限制在卡片与配置页均说明。
- 浏览器发现共用样式与账号样式加载顺序使长表单多出 2px 外层溢出；
  先复现断言失败，再用专用 form 类提高局部规则优先级，移除二次滚动，未修改共用弹窗。
