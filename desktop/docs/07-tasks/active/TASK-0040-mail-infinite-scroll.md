# TASK-0040 邮件列表无限滚动

> 状态：进行中
> 负责人：@Codex | 创建：2026-10-28 | 优先级：P1
> 关联：TASK-0036 / TASK-0039

## 需求与目标

移除邮件列表底部“上一页 / 下一页”，改为在列表内接近底部时自动读取下一批并追加，
保留已经显示的邮件、当前阅读项与列表滚动位置。

## 范围

### 包含

- 复用既有 Messages(account, folder, offset) 接口，每批 100 条。
- 防重复请求、按 ID 去重、加载/失败重试/结束状态及后端偏移上限提示。
- 切换邮箱/分类或重置视图时清空分页并取消过期请求。
- 通过账号同步状态变化与显式刷新重验已加载范围，不让后台更新覆盖或丢失已追加数据。
- 中文/英语文案、关键路径单测、完整 verify 与真实滚动容器的浏览器检查。

### 不包含

- 后端分页协议、数据库迁移、远程同步策略、全文搜索、虚拟列表或新增依赖。
- 修改既有语言胶囊、账号添加向导、Git 提交/推送/分支和归档。

## 分析与取舍

- 当前 useMail 按 offset 读取并每 3 秒替换当前页，MailContent 的两个按钮驱动翻页；
  直接只删按钮会导致无法继续读取，简单追加又会被轮询覆盖。
- 仓储固定每次 100 条、offset 范围 0～1,000,000，排序为 received_at DESC / id DESC。
- 提取独立列表 Hook 处理加载状态和数据；在已有列表滚动容器内使用接近底部阈值触发，
  不新增 IntersectionObserver 兼容层或 UI 框架，键盘滚动同样可触发。
- 账号已有 3 秒轮询，可从 lastSyncAt 等同步状态识别数据更新；
  仅在同步戳或显式刷新变化时按已加载页数重新读取，避免每 3 秒重扫长列表。
- 客户端筛选仍只覆盖已加载集合，文案从“当前页”调整为“已加载”，不冒充全文检索。
- API 契约草稿仍描述 cursor，而真实桥接与仓储为 offset；本轮按真实接口实现 UI，
  在当前页面说明中明确两者差异，不擅自更改公开 API。
- 既有 TASK-0038 / TASK-0039 未提交成果全部保留；共享索引仅追加本任务。

- [x] 无上一页/下一页按钮，接近列表底部自动追加下一批。
- [x] 读取不并发重复触发；无重复 ID，不因追加清空选择或已有邮件。
- [x] 初次/后续读取失败可显式重试且不循环自动重试；少于一批时停止读取。
- [x] 切换邮箱/分类/重置后从首批开始，过期请求不能污染新视图。
- [x] 同步或显式刷新重验已加载范围，不退回只显示最后一批。
