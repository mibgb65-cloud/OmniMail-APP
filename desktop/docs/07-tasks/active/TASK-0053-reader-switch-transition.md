# TASK-0053 邮件阅读区连续切换与抗闪烁

> 状态：待评审

> 当前方向：满高骨架、分段入场、设置控制配色与实际阅读后的服务商已读回写；此前双页缓冲、禁止正文入场和逐封配色按钮均已被追加要求替代。

## 用户需求

切换邮件时阅读区缺乏自然过渡、闪烁明显；设计时长适当、连续且不刺眼的切换动画。
保留骨架屏、图片就绪、安全隔离和复制/外链确认等已实施行为。

## 当前事实与方案

- 工作树包含 TASK-0051/0052 未提交改动，不覆盖、不提交、不归档，也不沿用旧任务提交授权。
- 当前选择变化使详情暂时为空，立即卸载旧头/正文并出现骨架，详情回来又重建头信息和正文；
  HTML 准备完另有一次淡入，造成短时多次整块切换。
- 不仅给新节点加动画：采用最多两个阅读页的有界过渡缓冲，
  旧内容作只读视觉承接，新页后台准备就绪后整体交叉渐变和轻微位移。
- 统一整体切换约 280ms；过渡时抑制子正文首次入场，避免二次闪烁。
  不人为延迟网络请求，也不为了动画等待过久；动画完成按浏览器信号清理，异常有界兜底。
- 快速连续选择只提交最新目标，旧准备/动画回调不能覆盖新选择；缓冲不扩成邮件历史缓存。
- 离开旧邮件立即禁用复制/附件/链接与关闭旧链接确认，不能把保留的旧内容当新邮件操作。
- 慢加载在保留旧页时明确提示正在打开所选邮件；慢图片的主动先读操作必须可达，
  不因隐藏准备页而永久等待。空选择或切换账号清理旧内容，不跨账号保留可操作页。
- 处理外层旧滚动位置，不能在切换开始或动画结束把旧页突然跳到顶部；
  减少动态时跳过位移动画，继续保持正确的准备和交互门禁。

## 最终实现与验证

- `MailReaderTransition` 负责目标代次、就绪提交、最多两页与实际动画生命周期；
  过渡中发起的新请求不被取消，但只保留最新目标，不排队播放所有中间页。
  如果一次过渡尚未结束，新目标最多等待本次剩余的 280ms，而不是累积等待多轮。
- `MailReaderPage` 保存每封邮件自己的 UI/附件状态；`MailBody` 回调仅报告当前文档就绪，

  避免跨账号保留上一封内容。初次没有可保留页时仍使用骨架，动画不会伪造请求成功。
- 主题、中英文新增切换中与旧预览解释文案；CSS 只做 opacity/transform，
  时长由 Token 统一控制，减少动态时不等待退出时长。
