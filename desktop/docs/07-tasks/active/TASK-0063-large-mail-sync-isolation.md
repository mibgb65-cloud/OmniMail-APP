## 用户确认与范围
- 用户明确确认：原始邮件 100 MiB、单附件 50 MiB、纯文本与 HTML 解码总量 8 MiB；单封超限不阻塞其他邮件。
- 本轮授权包含相关数据库约束迁移与安全预算调整，不需要再次确认；不包含取消限额、降低 TLS、扩大外部图片授权、改发送上限或提交/推送。
- 保留摘要及已有正文/附件；单封失败不能被标为完整下载，不能把存在超限项的邮箱冒充全量同步成功。

## 初始状态与方案分析
- 工作树已有 TASK-0061（UI/邮件计数）和 TASK-0062（三家预设）的未提交变更，全部保留。
- 当前上限散落于 MIME、服务、附件流式缓存与完整性读取、HTML 清洗及 SQLite CHECK；网络连接总预算 64 MiB，后台常规批次预算 32 MiB，必须协同调整。
- 现有后台正文失败立即终止账号；固定超限必须持久记录并从自动正文待办中排除，继续其他邮件/文件夹，但对外显示“部分邮件未完整下载”。
- 优先新增迁移，保留旧迁移校验和；迁移方式、错误分类、重试/恢复语义在后续分析后补齐，不直接更改旧 SQL 或吞掉非大小错误。
- 采用 schema v4：用新增/复制/替换受限列的方式放宽 HTML 和附件大小约束，不重建父邮件表、不触发级联删除；沿用现有迁移前备份和事务。
- 每封持久化固定白名单 `body_error_code`，自动正文待办排除已确认超限项；摘要保留，已有缓存仍可读，显式单封重取成功才清除标记。
- 账号摘要提供持久未完整下载数量；后台 `More` 仅表示还有可处理待办，超限项另显示“部分邮件受限”，不使用一直转动或成功绿点冒充完成。
- MIME 解码失败会关闭当前 FETCH 连接：记录单封后主动让出并续排新连接，不能在已关闭的连接上假装继续。按摘要大小预判的原始邮件超限可在同连接直接跳过。
- 独立保留邮件头 1 MiB、内嵌图片尺寸/数量/授权、发送正文 1 MiB、MIME 部件数量和并发/时间预算；连接读取预算改为 128 MiB，普通后台批次仍为 32 MiB，单封大邮件仅在新连接独占读取。
- 先区分原始邮件/单附件/正文/部件数量的静态错误码，再决定哪些错误可隔离；连接总预算、网络、取消、存储等错误不能被持久误判为某封邮件过大。

## 遗留风险
- 未用真实服务商账号收发 100 MiB 邮件，未迁移用户生产库；macOS WebView 未验证。
- 大规模库迁移需要额外磁盘备份空间和表改写时间，生产耗时/断电恢复未基准验证。
  新 v4 不保证可被旧版程序打开，降级需先备份现有数据并评估升级前备份恢复的数据时间点。
