## 需求与范围

用户反馈初次读取邮件时先露出一小块半成品内容和 iframe 内部滚动条。
按“骨架屏”理解用户“鱼骨屏”：从左向右流光，等待允许加载的邮件内容准备完毕后动画显示；
邮件 HTML 内不出现上下左右滚动条，由外层右侧阅读区统一滚动。

本轮不修改图片许可、外链确认、星标/同步并发、后端下载或数据库，不执行邮件脚本。
禁用或拦截的图片不算尚未完成的资源，不为了等待就绪而擅自开启远程图片。

  可由用户选择先阅读正文，图片后续加载继续更新尺寸。不自动解锁额外网络权限。

## 实现结果

- `MailSkeleton.tsx/.module.css`：统一骨架布局、无障碍状态、左至右流光；网络读取和 HTML 准备共用。
- `MailBody.tsx/.module.css`：允许的图片 load/decode、尺寸测量及两次 RAF 后才揭开文档；
  使用文档递增版本标记隔离迟到回调，A→B→A 不误复用旧就绪状态，StrictMode/缓存 load 可恢复。
  12 秒后提供主动先读，不自动揭开半成品；失败图片明确提示，超大布局回退所提供的完整纯文本。
- `mailFrame.ts`：根据自然宽度/高度排版，普通长文完整扩展 iframe；
  ResizeObserver 处理尺寸变化，清理监听/RAF，框架内部不暴露横竖滚动条。
  鼠标原生滚动链与父页面键盘处理统一至 `data-mail-reader`，
  不拦截链接激活、Tab、文本选择的 Shift+方向键或修饰键快捷键。
- `mailDocument.ts`：可信测量包装、内部 overflow/滚动条关闭、固定宽容器响应式约束；
  仅在无法收敛时缩放；剥离视口单位样式避免 iframe 高度自反馈，无脚本/CSP 与图片许可不变。
- `MailContent`/Token/语言包：初次请求骨架，稳定外层滚动占位，中英文慢加载与安全回退提示。
- 更新详情页当前实现说明；没有后端、数据迁移或依赖变动，没有主动操作真实邮件或外部站点。
