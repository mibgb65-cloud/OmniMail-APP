## 需求与目标
- 将截图中的浏览器原生断开确认框替换为软件统一风格的确认弹窗，保持已下载邮件保留的原有语义。
- 邮箱卡片压缩为单行，邮箱文字后使用状态点；成功为绿色、失败为红色。
- 悬浮成功状态显示“已同步 xx 封邮件”，失败状态提供重试按钮。
- 同步中仅在卡片外层 1.5px 或 2px 边框展示多彩顺时针 conic-gradient 循环动效，保留圆角和内部背景；支持减少动态效果偏好。

## 范围
- 包含：侧栏邮箱卡片、同步状态展示、确认交互、中英文文案与相关测试及页面文档。
- 不包含：同步协议、数据库结构、账号清除语义、依赖升级、提交与推送。

- 初始工作树干净，无用户既有改动。
- 已定位 `MailboxAccounts.tsx` 使用 `window.confirm`，卡片状态为独立一行；后续先核对共用弹窗、悬浮层与同步数据契约再决定复用方式。
- 优先复用现有组件和语义色，不新增 UI 框架或依赖。
- 确认使用 `DialogFrame` / `useDialogExit` 复用圆角、遮罩和退出门禁；可交互状态层独立于纯文本 Tooltip，以 Portal / Popover 避免滚动裁切。
- 现有 `AccountSummary` 没有总数：在仓储增加只读按账号聚合查询，摘要以可选 `messageCount` 传递真实本地邮件记录数（跨文件夹实例，不按 Message-ID 去重），不新增迁移、不改变同步协议。
- 重试通过控制器定向调用已有 `synchronize(id)`，不先切换账号或破坏当前邮件筛选。
- 实施拆为四步：确认弹窗；计数数据链路；状态/重试/样式；文档与全量验证，各步单独控制文件数和行数。

## 实现结果
- 已复用标准弹窗，默认取消、支持 Esc、确认防重复、退出后恢复入口焦点。
- 已增加只读 `MailCounts` 聚合及兼容的可选计数字段，生成绑定，不新增依赖/数据库迁移；计数读取失败不吞错。

- 卡片高度为 40px；状态点与选择/断开按钮互不嵌套。认证失效保留重新登录说明，不提供必然失败的无效同步入口。

- 原卡片、状态组件、统一弹窗及计数数据链路已审阅；仅生成绑定新增一项可选字段，未修改依赖、同步协议或数据库结构。
