# TASK-0080 自定义服务商模板保存与复用

> 状态：待评审
> 负责人：@Codex | 创建：2026-11-01 | 优先级：P1

## 需求
用户要求将自定义服务商连接配置保存，下次直接在服务商选择页点击复用，
只需补邮箱账号与登录凭据，不再重复输入服务器等参数。

## 范围与安全边界
- 新增本地服务商模板：名称、收发服务器、端口、TLS 模式。模板不能含用户名、密码、令牌或邮箱账号。
- 服务商选择页增加创建入口和已保存卡片；手动配置页增加从当前连接参数保存模板的入口。
- 已保存模板复用当前自定义账号路径与收发凭据策略，服务器配置以简要信息展示，不要求重复填写。
- 模板与账号独立；本轮账号仍以既有 `custom` 类型保存，不改既有账号或数据库结构。
  此方案仅扩展服务商选择/连接模板，不擅自改“我的邮箱”服务商分组的持久化语义。
- 保存模板不执行网络连接，不表示认证成功；添加账号仍通过原有 IMAP/SMTP 验证和系统凭据存储。
- 仅创建与复用；不附带改名、覆盖或删除已有模板，避免超出本轮需求。
- 不新增依赖、数据库迁移或第三方服务；保留工作树中所有 TASK-0073～0079 修改。

## 分析与方案
- 当前预设由 Go 固定列表提供；`custom` 表单可编辑参数，但未保存可复用的服务商数据。
- 增加数据目录下独立、小容量、受限 JSON 配置，接口只接收连接参数 DTO。
  Go 校验名称、主机、端口、TLS、协议/数量、总容量与唯一名称，原子保存、错误脱敏。
- 内置预设保持原接口；新增模板桥接与前端组合，模板读取失败明确提示，不冒充空列表或阻塞内置服务商。
- 复用现有服务器字段组件和账号凭据逻辑；选择模板时只填连接参数，
  从当前表单保存时保留本次账号输入，但模板内容绝不包含这些输入。

## 最终实现
- 新增 `domain/custom_provider.go`：模板及不含凭据的 ProviderServer 类型、白名单校验、数量与唯一性边界、
  到既有 ProviderPreset 的投影。内置预设仍保持独立列表与接口。
- 新增 `config/custom_providers.go`：当前数据目录的 `custom-providers.json`，版本 1、64 KiB、最多 32 条；
  校验普通文件、未知字段与完整 JSON，使用 `os.Root`、随机排他临时文件、同步和原子替换。
- 新增服务与薄桥接 List/Create，在应用中注册；互斥协调同名并发创建，
  名称/主机规范化，不接受明文连接，坏文件不会被当成空列表静默覆盖。
- 新增前端桥接边界校验（代码、名称、DNS/IP 主机、协议、端口、TLS、数量与重复代码），
  10 秒取消和白名单错误码，不附带原始路径/诊断。
- 服务商选择页新增“添加自定义服务商”和已保存卡片；模板读取失败会提示但内置卡片仍可用。
  新增模态编辑器，只接收名称及连接参数，复用抽取的 ServerFields，不提供认证字段。
- 手动配置可“保存为服务商”，只投影当前连接参数，当前账号输入不丢失。
  选择模板后连接参数改为摘要，保留账号、用户名、密码及 SMTP 凭据策略，不要求再填写主机等参数。
- 模板保存成功后等待编辑器退出再切入账号表单；取消和重复提交受同一请求生命周期约束。
  切回列表立即看到卡片，新窗口读取本机文件，凭据仍从空值开始。
- 账号仍提交既有 `custom` 路径，验证/系统凭据存储逻辑未更改；中英文与页面规范已更新。
