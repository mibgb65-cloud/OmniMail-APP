# TASK-0050 星标与正文读取不被后台同步阻塞

> 状态：待评审
> 负责人：@Codex | 创建：2026-10-30 | 优先级：P1
> 关联：TASK-0049

## 需求与验收目标

用户反馈星标操作缓慢、后台同步影响其他操作，并补充正文也一直显示等待账号空闲。
修复同账号同步、正文读取和星标写入之间不必要的互斥；星标立即反馈、失败可回滚，
后台状态刷新不能取消正文请求或覆盖新星标。不将网络本身的耗时宣称为已消除。

## 当前分析与边界

- `readMessage` 和 `SetStarred` 都使用 `s.claim(accountID)`，与同步共用 `s.active`，
  同账号只要在同步就返回 BUSY；再叠加全局三连接额度，前台操作可能继续排队。
- 前端正文请求依赖全局 revision 和同步状态变化，后台轮询/星标刷新会取消并重发在途正文请求。
- 前端所有星标共用一个 pending，服务器确认前没有即时反馈，还会阻止其他邮件的星标操作。
- 不能只删除互斥：同步已 FETCH 的旧 Flags 可能晚于用户星标完成才写库，覆盖新状态；
  断开账号仍需保护凭据生命周期，网络并发不能无限增加。
- 保留已有所有未提交改动，不提交/推送/归档其他任务，不新增依赖或 schema。

## 实施方案与分步计划

每步不超过 10 个文件、600 行；超过再拆步。

1. [x] 更新为进行中并登记索引，先正常关闭开发窗口，补可控慢同步/前台操作失败测试。
2. [x] 后端拆分有界同步、正文与标记通道：同账号最多一个后台同步、一个正文连接和一个标记连接；
   正文/标记具有独立全局额度，不因后台占满连接池而等待；断开与关闭仍安全。
3. [x] 为同步 FETCH→持久化增加标记版本检查：星标服务器确认后，过期批次丢弃并重取，
   不持锁等待长网络请求，不永久屏蔽其他客户端的服务器标记变化。
4. [x] 正文请求仅因选择/手动重试/手动重新获取而重建，不依赖同步轮询和星标列表刷新。
5. [x] 星标按邮件立即呈现期望值与保存中状态；不同邮件可独立提交，
   同一邮件保存中防重复；确认前不冒充已落库，失败只回滚该邮件。
   列表刷新与正文刷新解耦，后台旧列表不能闪回尚在保存的星标。
6. [x] 回归取消、错误、断开保护、同步竞态与多邮件操作；完整 verify、脱敏前端检查，
   更新当前实现文档与真实风险，恢复开发窗口。

## 风险与非目标

- 每个服务商仍有连接数限制；采用固定额度，不创建无界连接或关闭 TLS 验证。
- 新请求仍可能因服务商限流、网络、同类操作队列耗时；不承诺真实网络请求“瞬间完成”。
- 星标是会话内乐观显示，不新增持久离线写队列；网络失败回滚并明确报错。
- 断开账号是显式撤销连接能力，不视为必须与收发/星标并行的普通操作。
- 不使用真实账号/邮件作为测试夹具，不升级 Wails 或替换邮件库。

- 已正常关闭开发窗口，保留所有既有改动和开发数据。
- 后端首轮新增测试按预期失败：正文遇同步 active 直接 BUSY；在途旧 Flags 覆盖用户刚提交星标。
  拆分有界通道与版本校验后，service/mailnet 阶段回归通过。
- 追加覆盖：慢正文不阻止星标或启动同步；同类通道有界且可取消；
  凭据撤销仍与前台连接互斥；远端已确认但本地保存失败也使旧 Flags 批次失效。
- 前端首轮新增测试按预期失败：一次同步状态轮询使正文发起 2 次；旧星标 Hook 不提供即时显示。
  改为选择驱动正文、按邮件临时状态后，定向测试通过。
- 星标使用非 SILENT UID STORE 的 Flags 回执，移除冗余 FETCH，不减少 UID/Flag 校验。
- 浏览器使用真实 useMail/阅读器/列表组件与慢响应脱敏 API：
  后台持续运行，正文 3.5 秒、星标 1.8 秒；界面约 35ms 呈现星标且标记 busy，
  可以同时提交其他两封，失败仅回滚对应一封；正文仅请求 1 次、取消 0 次，星标分类最终 2 项。
  此耗时仅是受控夹具的本地 UI 反馈，不是实际服务商性能承诺。
- 首次完整 verify 被前端 `set-state-in-effect` 静态规则拦截；未关闭规则，
  改为按当前数据库快照派生有效临时状态，并仅在实际操作回调中更新状态。
- 当前环境 `go env CGO_ENABLED` 为 0，未启用 Go race 工具链；不将锁/并发用例通过冒充 race 检测通过。

## 实现结果

- `foreground.go` 为正文和标记提供按账号串行、跨类别独立的通道；与后台三连接额度分离，
  正文全局最多 3、标记最多 2，同账号最多 3 个不同用途连接。没有无界建连、共享 SELECT 状态或忽略 TLS。
- `Disconnect` 使用独立凭据撤销门禁，活跃前台连接未结束时不能删除凭据；
  同类排队、关闭和超时仍响应 context，不因为移除后台互斥而突破生命周期边界。
- 星标服务器确认后递增账号标记版本，同步在短提交临界区核对 FETCH 前的版本，
  发现过期则不推进游标、重取当前区间。远端成功而本地保存失败同样失效旧批次，
  不伪造服务器与 SQLite 原子事务。
- 读取排队后重验本地正文，避免同一正文已由另一窗口落库却重复下载；
  前端 `useMailReader` 不再订阅全局列表 revision 或同步状态，保留明确选择/重试的取消规则。
- 星标 UI 按邮件持有临时期望值与保存中状态，其他邮件不会全局禁用；
  新数据库快照接管后不继续遮盖服务器变更，失败仅回滚对应邮件并触发重验。
  切换到星标分类仍能看到本账号未保存完成的项目，不串入其他指定账号。
- `UID STORE` 直接核对非 SILENT Flags 回执，保留 UIDValidity/UID/Flag 检查，
  比原路径少一次额外 FETCH 往返；仍不承诺 TLS、认证或真实服务器耗时消失。
- 新增失败复现与回归覆盖，更新主界面、详情页和总体架构的当前实现说明。
