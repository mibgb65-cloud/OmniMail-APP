# 复盘记录（retrospectives）

> 状态：已生效 | 最后更新：2026-10-15

每次迭代结束、每次 P0 事故后各写一篇。命名：`YYYY-MM-DD-<主题>.md`。
复盘的目标是**改变系统**（流程、测试、文档、工具），不是评价人。

## 模板

```markdown
# RETRO YYYY-MM-DD 主题

> 类型：迭代回顾 | 事故复盘
> 参与者：@a @b @c
> 关联：TASK-xxxx / BUG-xxxxxx-xx / 里程碑 Mx

## 1. 发生了什么（事实，不带评价）
按时间线列出关键事件与数据（耗时、次数、错误码）。

## 2. 影响
- 用户影响：
- 数据影响：
- 进度影响：

## 3. 做对了什么（可复用）
- ...

## 4. 哪里出问题（根因，不是"谁"）
用 5 Whys 找到可修复的系统缺陷：
1. 为什么 A 发生？→ 因为 B
2. 为什么 B 存在？→ 因为 C

## 5. 行动项
| # | 行动 | 负责人 | 截止 | 验证方式 |
| --- | --- | --- | --- | --- |

> 行动项必须可验证，写"加强评审"不算。示例："为 bridge 层新增错误码映射测试",
> 验证方式："`TestBridgeErrorMapping` 覆盖 10 个错误码"。

## 6. 沉淀到规范
- [ ] 已更新 00-guidelines/<文件> 第 N 条
- [ ] 已更新 05-testing/test-cases/
```

## 规则

1. 复盘在事件/迭代结束后 **48 小时内**完成，避免记忆流失。
2. 行动项不超过 5 条，超出说明没有聚焦。
3. 每次复盘至少沉淀 1 条规范或 1 个测试用例，否则视为无效复盘。
4. 事故复盘需同时检查：是否能在 5 分钟内发现、是否能数据恢复、是否有用户可见提示。
