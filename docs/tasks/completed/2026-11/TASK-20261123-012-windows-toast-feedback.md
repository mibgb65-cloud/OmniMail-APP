# TASK-20261123-012 Windows 测试通知与实际提交状态

状态：Completed

## 需求与现状

- 用户点击测试通知后只有应用内成功提示，Windows 未显示系统通知。
- 前端不等待发送结果，并误将测试操作视作授权；后端未注册 Windows 通知标识，只异步启动 PowerShell，没有处理发送失败。

## 方案与验证

- 沿用 Windows 自带的 WinRT 通知通道，注册当前用户的应用通知标识，并检查系统通知状态及发送结果。
- 邮件文本通过标准 XML 编码和独立输入传递，不进入命令；实际邮件通知仍不显示正文，后台发送不中断邮件同步。
- 测试不修改应用设置；界面呈现提交、禁用或失败，而不声称系统一定弹横幅。
- 补充 XML 边界与错误映射回归测试、Windows 手工验收步骤，运行 `task verify`。不启动应用、不打包、不提交，保留现有 AI 侧栏改动。

## 实施结果

- 向当前用户注册 OmniMail 的 AUMID，固定 WinRT 调用并从标准输入传送 XML；识别 Windows 明确禁用、策略拒绝、发送失败和超时，系统未返回权限状态时不误报禁用。
- 测试入口等待后端返回，按结果显示「已提交给 Windows」或错误说明，不修改新邮件通知开关。新收件通知使用有界后台队列，避免启动过多进程和阻塞邮件同步。

## 验证与限制

- `task verify` 通过；新增了 XML 特殊字符、Unicode 长度边界和错误反馈回归测试。当前 Windows 上以只读方式检查，既有 OmniMail AUMID 注册项不存在；实际脚本干跑验证了 WinRT 对象、权限状态缺失时的回退以及 UTF-8 XML 解析，未调用 `Show`。
- 未启动桌面程序或实际发送系统通知，横幅与通知中心效果待按[冒烟步骤](../../../development/TESTING.md#桌面窗口手工冒烟)复验。已更新[架构](../../../architecture/OVERVIEW.md)，未提交或打包 Beta。
