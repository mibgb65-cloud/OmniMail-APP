# TASK-20261124-001 · 拆分邮件摘要与拟稿

- 状态：Completed
- 需求：对齐 OmniMail 设计稿的 AI 设置及邮件操作，摘要与拟稿独立，增加默认关闭的阅读自动摘要。
- 当前行为：同一分析请求生成摘要和草稿，保存后统一标记邮件已摘要。
- 方案：拆分 Wails 接口、提示词和 SQLite 字段更新，保留现有缓存结构；在展开的阅读面板中先查缓存，再防抖触发可取消的纯摘要。仅自动摘要可在明确启用后跳过逐次确认，其余请求仍经隐私守卫。
- 验证计划：验证 SQLite 缓存、两类字段合并、隐私守卫、取消和前端自动触发条件；执行 `task verify` 与 `pnpm build`。

## 改动与验证结果

- 从本地 `OmniMail-redesign.fig` 读取「设置 · AI 服务」和「Omni AI · 摘要与拟稿彻底分离规范」亮暗设计帧；实现模式徽章、默认关闭的开关、双卡及原文/中文拟稿切换。
- 分别生成 Wails 摘要和拟稿绑定，SQLite 原子合并字段并保留聊天历史。仅摘要成功时写入列表标记。已缓存的旧版摘要继续可用。
- 自动摘要仅由显式阅读与展开面板驱动，缓存判重、300ms 防抖、离开时取消；本会话失败或被拦截的邮件不会自动重试。自动路径不调拟稿或追问，不订阅同步事件。敏感拦截在面板静默提示，云端脱敏不因使用远程 Ollama 而跳过。
- `task verify` 通过（生成绑定、格式检查、Lint、类型检查、30 项前端测试、`go vet ./...`、`go test ./...`、Windows 开发程序构建）；`pnpm build` 通过，Vite 提醒主包超过 800 kB。
- 验证使用本地 SQLite 和模拟模型端点，没有连接真实邮箱或云端模型。未启动桌面应用做视觉走查，未发布、未提交 Git。
