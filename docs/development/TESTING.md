# 测试与质量门

| 命令 | 用途 |
| --- | --- |
| `task test` | 生成最新 Wails 绑定和前端产物，运行前端与 Go 单元测试 |
| `task verify` | 安装锁定依赖、检查 Go 与前端格式、运行 ESLint / TypeScript / Vite 构建、前端与 Go 单元测试、`go vet` 与开发构建 |

## 自动化测试覆盖

- **前端单元测试（`task frontend:test`）**：覆盖滚动边界、尺寸和正文变更、键盘焦点与监听器清理，以及 Heroicons 的 SVG 规格和关键图标映射；不启动原生窗口。
- **纯 Go 单元测试（离线可重复执行）**：覆盖桌面引导与双轨版本号解析（`desktop`）、DPAPI 凭据盒与 Argon2id PIN 锁及 HTML 净化（`internal/security`）、SQLite WAL 16 表与 Zstd CAS 存储（`internal/storage`、`internal/profilemgr`）、10 家服务商解析与 CJK 解码及 `.ics` 冲突检测（`internal/mailproto`、`internal/oauth`）、幂等同步与 FTS5 混合检索（`internal/syncer`）、RFC5322 BCC 零头泄露与零网络真撤回（`internal/outbox`）、联系人/黑名单/规则干跑/防循环自动回复（`internal/contacts`、`internal/rules`）、5 步 `PrivacyGuard` 与脱敏诊断包（`internal/ai`、`internal/diagnostics`）。
- **可选真实邮局非破坏性协议验证（`//go:build live`）**：在配置本地临时环境变量 `OMNIMAIL_LIVE_ACCOUNTS_FILE` 时，可在 `desktop/` 下执行 `go test -tags=live ./internal/syncer ./internal/outbox` 进行只读 `BODY.PEEK[]` 多邮局连通验证（严禁在仓库内写入任何真实账号或凭据）。

## 桌面窗口手工冒烟

涉及原生窗口、系统托盘、本地空间切换或 WebView2 动效时，可执行 `task dev`（或 `task build` 后运行 `task run`）核验冷启动开屏、三断点响应式布局、亮/暗主题扩散切换与 4 步连接探测握手反馈。

- 将主窗移离屏幕原点后最大化，通过托盘菜单「退出」结束进程再正常启动。主窗应完整覆盖原显示器工作区，不需最小化恢复；当次冷启动应播放一次开屏。
- 关闭主窗使其隐藏至托盘，再点击托盘图标恢复。已有主窗应直接显示，不重播开屏。用 `--silent-tray` 启动时也不应自动显示主窗或播放开屏。
- 在「设置 → 隐私」关闭默认拦截后查看带远程图片的普通邮件，不应显示拦截提示；重新开启则仍可单封放行。高风险邮件仍应强制拦截并显示钓鱼警示。
- 在已有其他账户后台同步时新增邮箱，弹窗应只显示新邮箱的进度。计数未知时只显示阶段；空收件箱不应显示虚构的 `1 / 1`，同步失败也不应显示完成。
- 打开一封邮件，在宽屏（≥ 1440 CSS 像素）连续点击「展开 AI」「收起 AI」。侧栏应整块左右滑动，中途反向应从当前位置折返，阅读区宽度跟随且结束时不跳变。缩到窄屏后侧栏改为浮层，阅读区宽度不变；确认可通过遮罩、关闭按钮或 `Esc` 收起。启用系统「减少动效」后，开关应直接切换。
- 展开、收起和拖动 AI 侧栏，特别是阅读区约 430–600px 宽时，检查阅读工具栏始终单行、正文不被工具栏换行推移。触发翻译中、部分译完和已译状态，再切换不同邮件计数，检查按钮占位不变。窄幅时低频操作进入「更多」，翻译、上一封/下一封和 AI 仍可访问；极窄时可横向滚动或用 Tab 访问，不新增第二行。
- 在亮、暗主题及收件箱、归档等视图下，确认「翻译」始终位于「标签」与删除之间；检查浮层跟随按钮、点击外部或 `Esc` 只关闭浮层。配置一个模型后，对含表格、图片和代码块的外文邮件确认翻译；切换原文、仅译文、双语及主题开关，核对图片策略未变化、右侧 AI 不消失。检查外文摘要语言、原文语言草稿插入快捷回复，以及模型失败时原文仍可阅读。
- 使用本地模拟翻译端点控制第二批返回：第二批等待时首批正文和可选主题已经显示；双语不附加空译文。翻译中切回原文后应保持原文模式；切换邮件/工作空间不串内容。第二批失败只显示「部分翻译失败」，保留已经显示的译文并可用相同选项重试。滚动到正文中部，检查增量不会重置阅读位置或重新加载图片。
- 在本地测试工作空间导入同名而包含 8 或 50 个长邮箱地址的联系人。亮、暗模式与窄窗口下，确认工具栏不换行、44px 提示条只显示组名与数量。关闭提示后仍可用「整理重复项」打开审阅；每组默认两行，展开后仅组内滚动。更换主邮箱、排除一个地址，核对底部精简数与确认文案；合并后查看备用邮箱、VIP 与往来历史，确认排除项仍单独存在。
- 拖动 Omni AI 左缘的分隔线，再用方向键和 `Home`/`End` 调整；检查宽屏阅读区不会被挤没、窄屏浮层不挤压阅读区，且重新启动后恢复首选宽度。提问检查 Markdown 加粗、列表、代码和长词换行；切换邮件、重启后检查原邮件仍可恢复已完成问答。打开与关闭「允许附带正在阅读的邮件主题」，对照侧栏提示和发送确认；两种模式均不发送附件文件、文件名或预览。
- 对一封普通邮件成功执行「总结当前邮件并起草建议回复」，确认邮件卡片右下角立即显示「AI 已摘要」。切换文件夹、刷新列表、重启应用后标记仍应存在；只提问、只翻译或摘要失败的未摘要邮件不应出现此标记。
- 选中一个有多封未读邮件的账户并进入「未读」。停留数秒，确认首封自动预览不会标为已读。单击一封邮件或通过上一封/下一封打开，只取消该封的未读样式并更新计数，不移除列表项；切换筛选再回来或手动刷新后，已读项才从未读清单清除。
- 邮件列表滚动超过 240px 时，检查底部回顶胶囊、48px 渐隐及头部阴影；亮暗主题下点击胶囊、手动回顶或切换账户/文件夹/筛选后，确认胶囊收起且底部可点击。深滚动时同步当前视图和其他视图的新邮件，确保只统计当前视图、同一封不重复计数，不跳动；返回顶部后加载并清零。开启「减少动效」时应立即回顶。
- 在 Windows 桌面版的「通知权限引导」中发送测试通知。开启系统通知且关闭勿扰时，确认任务栏附近出现 OmniMail 通知；只出现「已提交给 Windows」但无横幅时，同时检查 Windows 通知中心。系统关闭通知时，测试应说明未发送；不论结果如何，应用内新邮件通知开关不应改变。
- 在亮色、暗色以及窄屏抽屉中查看「我的邮箱」，用长短账号名和 `0`、`8`、`19`、`128` 未读数确认状态点和数字右对齐，且点击仍能切换筛选。
- 在「设置 → AI 助手」选 DeepSeek 等官方服务，确认没有 Base URL 输入，填入自己的密钥后获取模型，检查搜索选择和留空复用已保存密钥；切换提供方不应沿用上一家模型或临时密钥。自定义端点不支持 `/models` 时仍可手填并保存，测试连通性不应提前保存；同样检查免密 Ollama。非本机端点携带密钥时需要 HTTPS。
- 在亮色、暗色下分别检查工作台三栏、AI 抽屉、写信、设置和长下拉列表。短内容不出现遮罩；底部还有内容时显示渐变，滚到底后最后一行不被遮挡。拖动窗口或加载更多邮件后确认渐变自动更新，滚轮、触控板、方向键、底部点击和选中文本仍能使用；阅读区切换邮件回到顶部。PDF 附件的内嵌原生查看器不受应用 CSS 控制。
